# Phase 10 — UI Design Contract

> Visual and interaction contract for Phase 10 (FILL-01..04: login, TOTP, card, identity autofill). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Runs in **autonomous synthesis mode** per 10-CONTEXT.md — no human review loop; open product calls are picked with a sensible default and flagged below for confirmation at UAT, not left blocking.

---

## Scope Note — Where the Pixels Actually Live

This phase is **entirely popup-driven; it adds no visible in-page UI.** `content-relay` (D-01, ISOLATED world) is a pure DOM sensor/writer — it detects fields and writes fill values, but renders nothing on the host page (no icon-in-field overlay, no in-page dropdown). This resolves the "Discretion Area" left open in 10-CONTEXT.md/10-RESEARCH.md in favor of the MVP option research explicitly flagged as acceptable ("trigger fill from the popup's item list rather than an in-page overlay"). **Flagged for human confirmation at UAT** (10-CONTEXT.md Open Question 1): confirm this popup-only affordance is an acceptable Phase 10 "done" bar before an in-page icon overlay is considered (deferred to v0.2.x per FEATURES.md either way).

Consequence: every surface below is a new section/state inside the **existing extension popup shell** (Phase 9's unlock + item list + search), not a new content-script UI. The gesture-gate (D-03/D-12) is satisfied naturally: opening the popup (clicking the toolbar icon) is gesture #1, clicking a matched item's "Fill" action is gesture #2 (and, for card/identity, a third confirm click closes the loop per D-12's stricter bar — see Copywriting Contract).

The multi-account picker (D-07) is **not a separate UI** — it is simply the "On this page" section's own list when it contains more than one match. No additional component is needed.

## Spacing Scale

Declared values (must be multiples of 4) — same scale as `web/`, no new tokens introduced:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (e.g. Copy icon + "Copy" text) |
| sm | 8px | Compact row internal padding, badge gaps |
| md | 16px | Popup section padding, default row spacing |
| lg | 24px | Space between "On this page" section and the full item list below it |
| xl | 32px | Not used at popup scale this phase |
| 2xl/3xl | — | Not used — popup viewport is too small for these; reserved for the web app only |

**Exceptions:**
- **Popup width is fixed at 360px** (`docs/UI-DESIGN.md` §3: "szerokość ~360px") — every layout in this spec assumes this fixed viewport, not a responsive range. Do not design wider than 360px; do not assume mobile-style 44px touch targets (this is a mouse/trackpad-driven popup, not a touchscreen surface).
- **Icon-only action buttons (Copy, Fill icon on TOTP row) are 32px (`h-8 w-8`)**, not the usual 44px touch minimum — consistent with the existing `ItemRow.tsx` pattern (`h-8 w-8` favicon slot) and appropriate for a desktop popup's information density.

## Typography

Reused from `web/`'s established scale (`ItemRow.tsx`, `DetailPanel.tsx`, `TypePicker.tsx`) — no new sizes invented:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`text-base`) | 400 | 1.5 |
| Label / secondary | 14px (`text-sm`) | 400 | 1.5 |
| Caption / meta | 12px (`text-xs`) | 400 | 1.4 |
| Heading | 20px (`text-[20px]`) | 700 (`font-bold`) | 1.2 |

Only 2 weights declared project-wide: 400 (regular) and 700 (bold headings) — matches `docs/UI-DESIGN.md` §2 ("nagłówki 700+, body 400/500", codebase consistently uses `font-bold` not `font-semibold`).

**Monospace exception (phase-specific):** TOTP live code and the last-4-digits card hint render in `font-mono` at 16px/700 — same treatment as `TotpCountdownRing.tsx`'s existing `<span className="font-mono">{result.code}</span>`. This is the closest thing to a "Display" role this phase needs; there is no oversized hero-number surface in the popup (that's the web app's Health dashboard only).

## Color

Reused verbatim from `docs/UI-DESIGN.md`'s locked OKLCH tokens — no new colors introduced this phase:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `base-300` `#1F1F1F` (dark) / `#FCFBFA` (light) | Popup page background |
| Secondary (30%) | `base-100`/`base-200` `#262626`/`#212121` (dark) | "On this page" section card, item rows |
| Accent (10%) | **Primary coral** `#E16540` (`oklch(65.31% 0.1637 37.22)`) | Reserved for: the "Wypełnij" (Fill) primary button on each matched item row; the active/pressed state of the TOTP fill-icon button; the TOTP countdown ring (`text-primary`, matching `TotpCountdownRing.tsx` exactly) |
| Destructive/Error | `#FF5861` (`oklch(71.76% 0.221 22.18)`) | "Autofill unavailable on this page" banner icon/border only; fill-failed toast |

**Explicitly NOT used this phase:** teal accent (`#00CDB7`) — that color is reserved project-wide for passkey/passwordless semantics (Phase 12), and Phase 10 has no passkey UI. Do not color-code the card/identity confirm step with `warning` (`#FFBE00`) either — treat it as a neutral confirm (base-content, not warning-yellow), per "security UI always legible, playfulness never in security dialogs" — an extra confirm step is not an alarm.

## Copywriting Contract

Bilingual PL/EN per the project's existing `dictionary.ts` convention (`{ pl: "...", en: "..." }`); PL is primary.

| Element | Copy |
|---------|------|
| Section heading ("On this page") | PL: **"Na tej stronie"** · EN: "On this page" |
| Primary CTA — login fill | PL: **"Wypełnij"** · EN: "Fill" — button on each matched login/card/identity item row |
| TOTP row actions | Two icon-buttons, always both present: **"Wypełnij kod"** (Fill code, enabled only if an OTP-shaped field is detected on the page) and **"Kopiuj kod"** (Copy code, always enabled) |
| Copy toast (TOTP) | Reuse the *exact existing* web-app convention verbatim (`dictionary.ts` `toast.copied`): PL: **"Skopiowano kod. Wyczyści się za {n}s."** · EN: "Copied code. Clears in {n}s." — the extension's clipboard-clear-after-N-seconds behavior (30–60s configurable, `clipboard.ts`) must be replicated identically, not reinvented |
| Card/identity confirm (D-12's stricter gate) | Inline expand within the row (not a modal — popup is 360px wide, a stacked modal is cramped). PL: **"Wypełnić dane karty kończącej się na {last4} na tej stronie?"** / EN: "Fill the card ending in {last4} on this page?" — actions: **"Wypełnij"** / **"Anuluj"**. Identity variant: PL: "Wypełnić dane tożsamości „{label}" na tej stronie?" / EN: "Fill identity details for \"{label}\" on this page?" |
| Empty state heading (no on-page matches) | PL: **"Nic tu nie pasuje 🤷"** · EN: "Nothing matches here" — Fuzzy Bubbles annotation permitted here only |
| Empty state body | PL: "Żaden zapisany item nie pasuje do tej strony. Przeszukaj cały vault poniżej albo dodaj nowy." · EN: "No saved item matches this page. Search your whole vault below, or add a new one." |
| Error state (restricted page — `chrome://`, PDF viewer, etc.) | PL: **"Autofill niedostępny na tej stronie"** · EN: "Autofill isn't available on this page" — body PL: "Ta strona nie pozwala na wypełnianie z rozszerzeń. Skopiuj dane ręcznie z widoku itemu." / EN: "This page doesn't allow extension autofill. Copy the values manually from the item view." Plain, legible — no emoji (this is a limitation notice, not an empty state). |
| Fill-failed toast (field vanished after SPA re-render) | PL: "Nie udało się wypełnić — spróbuj ponownie." · EN: "Couldn't fill — try again." |
| Destructive confirmation | N/A this phase — Phase 10 is fill-only, no deletes/writes to the vault (see Phase Boundary in 10-CONTEXT.md). The only "confirm before proceeding" pattern is the card/identity inline confirm above, styled plainly (no destructive-red styling — this isn't a delete, just an extra consent step). |

**Cross-origin iframe refusal (D-04) is deliberately silent — no user-facing copy.** A subframe that legitimately has no matching item looks identical, in the UI, to a subframe whose cross-origin fill was refused: both simply produce no entry in "On this page" for that frame's context. Surfacing a "blocked for security" message on every innocuous third-party embed (payment iframes, ad frames, SSO widgets) would create constant, uninformative noise. This is a deliberate fail-closed-and-quiet design choice, not an oversight — **flagged as a review question** (10-CONTEXT.md Open Question, adjacent): confirm at UAT that silent refusal (vs. a subtle "some fields on this page were skipped for your security" disclosure) is the right call for v0.2.

## States

| State | Behavior |
|-------|----------|
| Loading | `OnThisPageSection` shows a single DaisyUI `skeleton` row (`h-12 w-full rounded-box`) while the `autofill.match` round-trip is in flight — should resolve in well under 200ms; do not show a spinner for longer than that without also showing the skeleton (avoids flash-of-empty-then-populate) |
| Populated — single match | One `AutofillItemRow`/`TotpFillRow`, no picker chrome needed |
| Populated — multiple matches (D-07) | `OnThisPageSection` simply lists all matches — this list **is** the picker, no separate dialog |
| Empty (no match) | `AutofillEmptyState` — Fuzzy Bubbles copy per Copywriting Contract, full item search remains available below |
| Error (restricted page / content-relay unreachable) | `AutofillErrorBanner` replaces `OnThisPageSection` entirely — plain, legible, no emoji |
| Fill in progress | Button shows a small inline spinner (`loading loading-spinner loading-xs`, DaisyUI) inside the "Wypełnij" button for the ~sub-second `autofill.fill` round-trip; button disabled during this window to prevent double-fill |
| Fill failed | `FillFailedToast`, button returns to idle state, item remains selectable to retry |

## Phase-Specific Notes

1. **No in-page visual footprint.** `content-relay` renders nothing; all UI is popup-hosted (see Scope Note above). If a future v0.2.x pass adds an in-page icon overlay, it needs its own UI-SPEC addendum — do not retrofit this phase's components into the page's DOM.
2. **Reuse, don't reinvent:** `TotpCountdownRing.tsx` (unmodified, same `size={24}` list-row treatment already used elsewhere), the `toast.copied` clipboard-clear copy/behavior, and `TypePicker.tsx`'s type→icon map are all direct reuses. The executor should import/adapt these, not rewrite them for the extension.
3. **D-12's "stricter than login" bar is expressed as an extra inline confirm step**, not a color/tone change — `SensitiveFillConfirm` is visually calm (base-content, no warning-yellow), because an additional consent click is not the same UX signal as a security alarm; over-styling it as a warning would violate "playfulness/alarm-tone reserved for actual security events" and cry wolf on every card fill.
4. **Popup width is non-negotiable at 360px** for this phase's layout math — do not design `AutofillItemRow`'s trailing button + type icon + two-line text stack any wider; truncate origin/labels with `truncate` (already the established pattern in `ItemRow.tsx`).
5. **Dark theme is the default surface assumed throughout this spec** (`docs/UI-DESIGN.md`: "Dark theme domyślny, light pełnoprawny") — light-theme token values are listed in the Color section's parenthetical for completeness; both must render correctly, but visual QA should default to dark.
