<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| MAIN-world page DOM (untrusted, any script the page runs) <-> closed Shadow DOM root | The page's own JS shares the same document but must not be able to read into or write onto the extension's injected UI, and the extension's injected CSS must not leak onto the page. No message-passing crosses this boundary — it is a DOM/CSS isolation boundary, not a data boundary. |
| ISOLATED content script -> background service worker | `generate-popover.ts`'s only outbound call: `sendMessage({kind:'generate-request', ...})`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-11-11 | Tampering / Information Disclosure | `inpage-mount.ts` | medium | mitigate | `attachShadow({mode:'closed'})` (the same pattern `inpage-overlay.ts` already uses) prevents the host page's own script from reaching `element.shadowRoot` to read or manipulate the injected popover/preview (e.g. scraping a previewed password or spoofing the "Use this password" button). |
| T-11-12 | Information Disclosure | Injected stylesheet's font handling | low | mitigate | No `@font-face` rule of any kind (self-hosted or CDN) is present — the stylesheet declares `font-family: "DM Sans", system-ui, -apple-system, sans-serif;` only (matching `inpage-overlay.ts`'s existing `OVERLAY_CSS` convention), so a page the extension injects content into never triggers ANY outbound font fetch, extension-scheme or third-party (orchestrator decision 2026-07-16: the earlier web-accessible-resources font requirement was itself unnecessary fingerprinting surface, superseded). |
| T-11-13 | Spoofing | Generate-trigger icon visual identity | low | accept | A malicious page could attempt to visually mimic the extension's own trigger icon inside its own DOM to phish a click. Accepted: the real popover only ever renders inside the closed shadow root, so clicking a page-forged lookalike opens nothing extension-controlled; this generic phishing-style risk is common to all password-manager extensions and is not closable within this phase's scope. |
| T-11-18 | Information Disclosure | Generate trigger mounted on the user's own vault app / a blocked origin | low | mitigate | X-4: content-relay.content.ts gates the generate trigger behind `isConfiguredServerOrigin()`/`isOriginBlocked(location.origin)` before mounting it, mirroring the Phase 10 overlay's identical suppression — the trigger never appears on the user's own configured server origin or an origin the user has explicitly blocked. |
