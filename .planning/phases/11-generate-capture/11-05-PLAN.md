<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Cross-origin iframe's MAIN-world page (untrusted, actively adversarial in the historical CVE-class case) <-> ISOLATED content script <-> background | The scenario this plan's headline mitigation exists for: a form embedded in a different origin than the top-level page must never have its captured credential silently attributed to the top-level page. |
| Closed Shadow DOM UI <-> host page | Reused unmodified from Plan 11-04 — the toast and modal render inside the same closed root, page JS cannot reach either. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-11-14 | Spoofing / Information Disclosure | `content-relay.content.ts` propose-response routing | critical | mitigate | This is the phase's headline requirement: whenever 11-03's independently-verified `mismatch:true` flag is set, routing goes to `mismatch-modal.ts` unconditionally — the toast path is never reachable in that case, closing the historical Bitwarden CVE-class "cross-origin iframe silently attributed to the top-level origin" bug (D-06 / ROADMAP Success Criterion 4). |
| T-11-15 | Tampering | `mismatch-modal.ts` dismissal behavior | high | mitigate | The modal is not dismissible via a scrim click or Escape — only the two explicit labeled buttons ("Cancel" / "Save anyway") close it, with focus trapped on mount (`role="alertdialog"`), so a user cannot accidentally proceed past the warning without deliberately reading and choosing. |
| T-11-16 | Repudiation / Information Disclosure | Save/update toast's password-reveal control | low | accept | A page-level clickjacking overlay could theoretically attempt to trick a user into revealing/confirming a save. Accepted: the closed shadow root's own stacking context means a page cannot dispatch a trusted synthetic click into elements it has no reference to; broader host-page clickjacking is a generic risk affecting every browser extension equally and is out of this phase's scope to close. |
