## Fixed Issues

### WR-04: `SelfTestCard`'s `mountedRef` guard is shared across effect invocations, so it does not actually prevent a stale `run()` from applying results after a React Strict Mode remount

**Files modified:** `web/src/components/self-test/SelfTestCard.tsx`
**Commit:** 87205a8
**Applied fix:** Read the actual component (matched the review's cited state exactly, lines 18-42). Replaced the single persistent `mountedRef` boolean (set `true` on mount, `false` in effect cleanup, reset back to `true` on every effect re-setup) with a per-invocation generation counter (`runIdRef`, a `useRef(0)`). Each call to `run()` — whether from the mount effect or the "Uruchom ponownie" retry button's `onClick` — captures `myRunId = ++runIdRef.current` at the start, and only commits `setState(...)` after each `await` if `runIdRef.current === myRunId` still holds. This closes the race the review identified: under React Strict Mode's mount → cleanup → remount cycle, the stale first invocation's `myRunId` no longer matches the counter (which was bumped again by the second invocation's `run()` call), so its late-resolving `setState` is correctly suppressed — unlike the old `mountedRef` flag, which got reset back to `true` by the second effect setup before the first invocation's promise resolved, letting the stale update through. Applied the review's suggested fix pattern directly since it matched the actual code closely; the only adaptation was dropping the now-unnecessary `mountedRef.current = true` assignment and cleanup callback, replacing them with an explanatory comment (the counter increments naturally on each `run()` call, so no separate mount/unmount bookkeeping is needed). The retry button's `onClick={run}` continues to work unchanged — each click gets its own `myRunId`.
