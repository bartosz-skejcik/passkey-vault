## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps, badge inline padding |
| sm | 8px | Compact spacing within nav rows, form controls |
| md | 16px | Default element spacing, mobile main-column padding |
| lg | 24px | Section padding within cards |
| xl | 32px | Desktop main-column padding, layout gaps between shell regions |
| 2xl | 48px | Major section breaks (e.g. above/below self-test card) |
| 3xl | 64px | Page-level spacing (reserved; unlikely needed for this phase's single-card layout) |

Exceptions: none — sidebar width (256px), top bar height (64px), and card radius geometry are already multiples of 4/8 and need no exception.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 20px | 700 | 1.2 |
| Display | 28px | 700 | 1.15 |

Two weights declared for this phase: **400 (regular)** and **700 (bold)**. UI-DESIGN.md allows body 400/500 and headings 700+; 500 (medium) is deferred until a later phase needs finer hierarchy (e.g. active vault-list rows in Phase 2) — not required for the Phase 1 shell/self-test.

- Label → sidebar nav items, top-bar search placeholder, self-test step names, badge text.
- Body → default running text, self-test summary line.
- Heading → section titles ("Crypto Self-Test", sidebar group headers).
- Display → page/route title in the main column (e.g. app wordmark).
- `Fuzzy Bubbles` 400 is not a sized role in this table — it is used inline at the surrounding body/label size, never in security-relevant output (self-test).

## Color

Values below are `vault-dark` (default theme). `vault-light` uses the same OKLCH hue/chroma for primary/accent/semantic tokens — only base/content surfaces shift (see note below).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1F1F1F` — base-300, `oklch(23.93% 0 0)` | Page background, main-column canvas |
| Secondary (30%) | `#262626` base-100, `oklch(26.86% 0 0)` (cards, incl. self-test card) + `#212121` base-200, `oklch(24.78% 0 0)` (sidebar, top bar) | Cards, sidebar, top bar — the two-step "surface family" per UI-DESIGN.md's flat/no-shadow system |
| Accent (10%) | `#E16540` — primary coral, `oklch(65.31% 0.1637 37.22)` | "+ Nowy item" CTA stub (top bar), active/selected sidebar nav indicator, focus rings, brand wordmark mark |
| Destructive | `#FF5861` — error, `oklch(71.76% 0.221 22.18)` | Reserved for destructive actions (none exist in Phase 1 — no delete/revoke UI yet); reused semantically for the self-test **✗ failed-step** indicator only |

Accent reserved for: the top-bar "+ Nowy item" button, the active/selected sidebar nav-item indicator (left bar or icon fill), focus-visible rings, and the brand wordmark accent. Never used for body text or decorative fills.

**Additional semantic tokens used by the self-test card (not part of the 60/30/10 split, but load-bearing for this phase's demo):**
- Success `#00A96E` (`oklch(64.80% 0.150 160)`) → self-test **✓ passed-step** indicator.
- Error `#FF5861` (same as Destructive above) → self-test **✗ failed-step** indicator.
- Teal accent `#00CDB7` (`oklch(74.51% 0.167 183.61)`, DaisyUI `accent` token) — declared in the `vault-dark`/`vault-light` theme CSS per UI-DESIGN.md §2 but **not visually used anywhere in Phase 1**. No passkey UI exists yet; the token exists for forward-compatibility with Phase 3/4 (passkey badges, "Odblokuj passkeyem" CTA). Do not repurpose teal for anything in this phase.

**Light theme (`vault-light`, full parity, manually toggleable, not default):** Dominant → `#FCFBFA` base-200 (`oklch(98.86% 0.0017 67.80)`); Secondary → `#FFFFFF` base-100 cards (`oklch(100% 0 0)`) + same base-200 for sidebar/top bar; Accent/Destructive/Success hexes are unchanged (OKLCH primary/accent/semantic tokens are theme-invariant — only base/content surfaces and text swap). Toggle must swap both `data-theme` value and any theme-scoped Tailwind class in one atomic operation — no residual dark-only hardcoded colors anywhere in the shell or self-test card.

All copy in Polish, founder-voice (per UI-DESIGN.md §4: "Twoje hasła, Twój serwer" tone). Fuzzy Bubbles + emoji permitted only in the empty-state row below — **never** in the error/self-test row, which is security-relevant output and must stay technical and legible.

| Element | Copy |
|---------|------|

| Empty state body | `Dodawanie itemów ląduje w kolejnej fazie — na razie sprawdź, czy krypto działa 👇` (points visually at the self-test card below). Fuzzy Bubbles font permitted here. |

| Destructive confirmation | Not applicable — Phase 1 introduces no destructive actions. Theme toggle and self-test re-run are non-destructive and instantly reversible. The destructive-confirmation contract begins in Phase 3 (passkey deletion with recovery warning, per AUTH-06). |

## Phase-Specific Notes

### Self-Test Card (this phase's demo — the primary visual deliverable)

- **Container:** base-100 surface (`#262626` dark / `#FFFFFF` light), 16px radius, 1px border (subtle neutral/base-300-toned border, no shadow), 24px internal padding.
- **Title:** "Crypto Self-Test" — Heading role (20px/700).
- **Step list:** `derive → wrap → unwrap → encrypt → decrypt`, one row per step:
  - Label (14px/400) naming the step, e.g. "Derive User Key", "Wrap", "Unwrap", "Encrypt item", "Decrypt item".
  - Status indicator: Lucide `Check` icon in a success-green (`#00A96E`) circle on pass, Lucide `X` icon in error-red (`#FF5861`) circle on fail. Icon size 16–20px. No textual ✓/✗ glyphs as the primary signal — icon + color carries the state, text stays plain.
  - Optional technical detail per row (e.g. truncated hex output) in `ui-monospace`, 14px, muted text color (`#ABA8A7` dark / `#595451` light).
- **Summary line:** plain text, e.g. "5/5 kroków przeszło" or "3/5 kroków przeszło — patrz błąd poniżej" — no emoji (security-relevant).
- **Optional manual re-run action:** DaisyUI `btn btn-sm btn-outline` in neutral tone (not primary coral) labeled "Uruchom ponownie" — intentionally not styled as the page's primary CTA to avoid competing with "+ Nowy item".
- Fuzzy Bubbles font must never appear inside this card.

### Shell Layout

- **Sidebar:** base-200 surface, fixed 256px width on desktop, DaisyUI `drawer` off-canvas on mobile. Contains: non-functional nav placeholders (Vault / Foldery / Tagi — Lucide icon + Label-role text, inert `aria-disabled` this phase) and a bottom account block (avatar placeholder + name placeholder + theme toggle).
- **Top bar:** base-200 surface, 64px height, 1px bottom border. Left/center: search input styled with DaisyUI `input`, `kbd` pill showing "⌘K" inside the field (non-functional stub). Right: "+ Nowy item" primary-coral button stub.
- **Main column:** base-300 canvas, 32px padding desktop / 16px mobile, content max-width ~640–720px. Contains a Display-role page/section title followed by the self-test card, spaced by the `2xl` (48px) token.
- **Theme toggle:** DaisyUI `swap` or equivalent button; persists to `localStorage` (e.g. key `pv-theme`); initial value read from `prefers-color-scheme` via an inline pre-hydration script (not a client `useEffect`) to avoid a flash-of-wrong-theme on load.
