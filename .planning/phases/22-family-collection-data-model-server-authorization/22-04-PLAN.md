<objective>
Make `vault.rs` collection-aware (SEC-06's "every mutating endpoint uniformly gated" applied to
the item resource that already existed before this phase) and build the "move item between
collections" endpoint that closes Vaultwarden #6269 — the phase's headline security fix — plus
the direct per-item share surface (SHARE-02's server half).

**Written-rationale deviation from CONTEXT.md, already decided per phase_specific_planning_notes:**
CONTEXT.md's SHARE-04 text only names the source-collection `edit` requirement. This plan adds a
SECOND gate — `edit` (not merely read) on the destination collection too — per the explicit
instruction already resolved in this phase's planning notes: an edit-capable member of one
collection must not be able to push items into a collection they hold a lesser (or no) grant on.

Purpose: this is where the phase's two structural corrections from RESEARCH.md converge —
`vault_items.collection_id` (added in Plan 22-01's migration) finally gets a real authorization
consumer, and the "move is a re-encrypt-and-replace, never a bare UPDATE" rule becomes an actual
endpoint contract.
Output: collection-aware `vault::update`/`delete`/`touch`, `PUT /api/vault/items/{id}/collection`,
`POST/DELETE /api/vault/items/{id}/shares[/{user_id}]`.
</objective>
