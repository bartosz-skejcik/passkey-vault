<objective>
Extend `crates/pv-core/src/items.rs` with a collection-scoped sibling to the existing
personal-scope item encryption path: new versioned AAD prefixes that bind the encryption scope
(now including `collection_id`), a length-unambiguous AAD builder, and
`encrypt_item_for_collection`/`decrypt_item_for_collection` entry points mirroring
`encrypt_item`/`decrypt_item` exactly. The existing personal-scope path
(`AAD_ITEM_KEY_PREFIX`/`AAD_ITEM_DATA_PREFIX`/`build_item_aad`/`encrypt_item`/`decrypt_item`)
is frozen byte-for-byte — this plan only adds new siblings, never touches the existing ones.

Purpose: KEY-03 requires item AAD to bind the encryption scope (personal vs. a specific
collection) so an item cannot be silently reinterpreted after moving between scopes — a
deliberate change from today's `prefix ‖ item_id ‖ revision` scheme, which encodes no notion
of which key wrapped the item. This plan is independent of the identity-keypair/sealed-box
work in Plan 21-02/21-04 (the Collection Key here is a plain 32-byte symmetric key, opaque per
this codebase's established newtype convention — how it gets sealed/distributed to recipients
is Plan 21-04's job, not this plan's) and can run in parallel with Plan 21-02.

Output: `crates/pv-core/src/items.rs` gains a `CollectionKey` opaque type, two new AAD prefix
constants, `build_coll_item_aad`, and the two new collection-scoped encrypt/decrypt functions,
plus a comprehensive cross-context rejection test suite.
</objective>
