<objective>
Deliver the X25519 identity-keypair primitive at the pv-core layer: add the audited
`crypto_box` dependency with the corrected (compile-verified) feature set, define the opaque
`IdentitySecretKey`/`IdentityPublicKey` types following the existing `UserKey` pattern exactly,
and wrap/unwrap the secret half under the account's `UserKey` via the existing symmetric
`aead_seal`/`aead_open` — no new symmetric crypto. This is the phase's tracer: the thinnest
slice that proves the new external dependency compiles and resolves cleanly against this
workspace's real lockfile (native and `wasm32-unknown-unknown`) before any further asymmetric
primitive (sealed Collection Key, Plan 21-04) or scope-bound AAD (Plan 21-03) work begins.

Purpose: KEY-01 requires every account to have an X25519 identity keypair whose private half
is wrapped by the UserKey and whose public half is publishable; KEY-05's dependent code (this
is the first code that depends on the Plan 21-01 decision record) must use exactly the
crate/feature set that record names; KEY-04 requires the new wrap constant to be distinct and
versioned.

Output: `crates/pv-core/src/identity.rs` (new module) with keypair generation and
UserKey-wrapping, registered in `crates/pv-core/src/lib.rs`, with `crypto_box` pinned in
`crates/pv-core/Cargo.toml` and tracked in `deny.toml`'s watch-list.
</objective>
