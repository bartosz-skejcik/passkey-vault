<objective>
Close the server-side half of Phase 7: `Config` gains a fail-fast `validate()` that turns a misconfigured `PV_RP_ID`/`PV_ORIGIN` pair into a specific, actionable startup error instead of a runtime WebAuthn `SecurityError` a user hits later (DEPLOY-02); `router()` gains an `Option<PathBuf>` static-directory parameter so the same axum process can serve the API, the sync WebSocket, and the static Next.js export on one port (DEPLOY-01); `build_pool` gains WAL + busy_timeout so the single SQLite file survives the sync hub's concurrency profile; and `main.rs`'s `shutdown_signal()` learns to trap SIGTERM (which `docker stop` actually sends) alongside the SIGINT it already handles, so container stops drain in-flight connections instead of always hitting the SIGKILL timeout.

Per 07-CONTEXT.md (locked): the localhost exception is scoped to the *pair* (`rp_id == "localhost"` OR `rp_origin`'s host is a localhost variant) so today's zero-config defaults keep working with no env vars set. Per 07-RESEARCH.md Pattern 3 (locked recommendation): `Config::validate()` does NOT duplicate `webauthn-rs`'s own IP-address `rp_id` check — that stays solely inside `build_webauthn`'s existing `WebauthnBuilder` call, already exercised by `build_webauthn_rejects_mismatched_rp_id_origin`. Per 07-RESEARCH.md Pattern 2 (locked recommendation): the static directory is threaded as a `router()` parameter, not a new `AppState`/`Config` field, since it's read once at router-construction time.
