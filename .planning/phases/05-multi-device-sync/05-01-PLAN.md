<objective>
Build SYNC-01's server-side half: a `users.vault_revision` monotonic counter bumped atomically alongside every existing vault-item/folder mutation, and a new `GET /api/sync?since=N` endpoint that cheaply reports "nothing changed" or returns a full item+folder snapshot when it has. Per 05-RESEARCH.md's own recommended build order, this is the strict prerequisite for everything else in the phase — Plan 05-02's WebSocket events reference the same revision numbers this plan introduces, and Plan 05-03's client poll/reconnect logic pulls against the exact endpoint this plan ships.

This plan deliberately does NOT touch WebSockets at all — SYNC-01 (the pull contract) is fully functional and testable on its own, independent of SYNC-02's push channel.

Purpose: a second device polling `GET /api/sync` can already observe a first device's create/edit/delete once this plan lands, with no unnecessary full re-fetch when nothing changed.
Output: `0010_vault_revision.sql`, an extended `vault.rs`/`folders.rs` with atomic revision bumps, and a new `sync.rs` pull handler — all proven by integration tests against a real (in-memory) SQLite database.
</objective>
