## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Clipboard contents | Shared OS-level resource — the auto-clear guarantee is the only defense against a password lingering there indefinitely |
| Concurrent edits to the same item (multi-tab/future multi-device) | Where a silent overwrite would be a real data-loss bug, not just a UX nicety |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-21 | Information Disclosure | Password left in OS clipboard indefinitely | medium | mitigate | `copyWithAutoClear`'s single-active-timer discipline guarantees the clipboard is overwritten after the configured duration regardless of toast dismissal; verified by a fake-timer test and a human-check pasting into a real OS clipboard |
| T-02-22 | Tampering | Silent overwrite of a concurrently-edited item | high | mitigate | `updateVaultItem`'s 409 path never mutates the local item optimistically — it re-fetches truth and surfaces `RevisionConflictError` to the UI, which shows a clear message and preserves the user's in-progress edit for a manual retry |
| T-02-23 | Tampering | Irreversible data loss via accidental delete | medium | mitigate | `DeleteConfirmDialog` is the only path to `deleteVaultItem` — no row-level one-click delete without confirmation |
| T-02-24 | Information Disclosure | Weak generated passwords due to biased RNG | medium | mitigate | `uniformRandomIndex`'s explicit rejection-sampling threshold, tested for `Math.random` absence and modulo-after-rejection ordering |

</threat_model>
