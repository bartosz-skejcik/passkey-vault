# E2E fixture hazard — DECISION for this plan (hazard #3, explicit)
web/playwright.config.ts:104 sets `retries: 2` against ONE shared server/DB and a fixed singleton
`FAMILY_OWNER_EMAIL` account, so vault items/folders accumulate across retries. DECISION: this plan
does NOT fix fixture isolation (out of scope, a standing hazard across every phase's e2e suite,
not unique to this one) — every new assertion in this plan is COUNT-AGNOSTIC. Never assert "exactly
N shared folders" or "exactly N items"; always assert the PRESENCE of a specifically-named,
uniquely-identified (via a fresh UUID-suffixed name generated per test run) folder/item, using
`toBeVisible()`/`getByText(exactName)`, never a list-length equality.
