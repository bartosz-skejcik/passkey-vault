<objective>
Give the client ONE place that fetches the new discovery endpoint, on the existing sync cadence, and
exposes its result synchronously to every consumer -- so the reseal-trigger (30-12) and the
pending-row UI (30-13) never each independently poll the same endpoint, and a single-user/no-family install
never pays a network tax for a capability it can never use.

Purpose: "one query, two consumers" (RESEARCH.md) implemented as one client-side fetch, two readers.
Output: `getFamilyWidePending()`, `familyWidePending.ts`'s store, `sync.ts`'s new optional hook.
</objective>
