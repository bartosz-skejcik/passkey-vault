<objective>
Widen the invite wire contract, additively, so one invite can carry the wrapped keys of every
family-wide collection that existed at the moment the invite was generated -- the invite-time-wrap
half of FSH-02's hybrid mechanism. The existing single-collection-scope invite path (one folder,
explicitly shared via invite) is untouched byte-for-byte; this is a NEW, parallel, always-optional
capability layered alongside it in the same request/response/accept cycle.

Purpose: without this, a family-wide share created before an invite is generated never reaches that
invite's invitee at all, no matter how the lazy-reseal fallback is designed.
Output: `CreateInvitationRequest`/`InvitationPublicResponse`/`AcceptInvitationRequest` carry an
additive `family_wide_keys`/`family_wide_sealed_keys` array; `create()`/`fetch_metadata()`/`accept()`
thread it through the existing transaction shapes.
</objective>
