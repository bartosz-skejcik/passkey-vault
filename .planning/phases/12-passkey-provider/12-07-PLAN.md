<objective>
Bartek live-review (2026-07-17, Chrome, github.com): when a site has BOTH a vault passkey and a login, the provider consent popup AND the Phase-10 in-page login overlay show at once — bad experience. Root cause: the provider intercepts every credentials.get()/create() (incl. GitHub's conditional-mediation autofill call fired on page load) with no coordination against the autofill overlay. Bartek's rule: PASSKEY ALWAYS PRIORITY — when the site wants a passkey, show the passkey and hide the login overlay; if the site doesn't want a passkey at this stage (ceremony falls through), show the login.

Implement that coordination inside content-relay.content.ts (which already hosts BOTH surfaces).
</objective>
