<objective>
Add the `passkey-rs` (1Password) soft ES256 WebAuthn authenticator to a new sibling crate `crates/pv-provider`, implement a vault-backed `CredentialStore` adapter, define this phase's HKDF domain-separation constant (D-08), and expose two new `pv-wasm` bindings that let the background service worker create/read provider passkeys WITHOUT ever letting the plaintext private key material surface as a JS-visible value — reusing `encrypt_item`/`decrypt_item` unchanged (D-07).

Every later plan (background orchestration, MAIN-world bridge, popup UI) calls into these bindings; getting the zero-knowledge property right here (no plaintext private key crossing the WASM->JS boundary as a return value) is what makes the rest of the phase's `/gsd-secure-phase` gate (D-15) passable.
Output: `crates/pv-provider` (new workspace member), `crates/pv-core/src/provider.rs` (new module), two new `#[wasm_bindgen]` functions in `crates/pv-wasm/src/lib.rs`, full `cargo test` coverage for the round-trip create->encrypt->decrypt->assert flow.
