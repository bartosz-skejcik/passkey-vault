<objective>
Harden the pv-server CORS boundary: replace the `Access-Control-Allow-Headers: *` wildcard with
an explicit `[authorization, content-type]` allowlist (SEC-01), and replace the `moz-extension://*`
scheme-wildcard origin predicate (D-10 tech debt) with concrete per-install origins only, while
keeping WR-07's bare-`*` rejection intact (SEC-02).

Purpose: Firefox does not treat `Allow-Headers: *` as covering `Authorization`, so today's wildcard
silently breaks the exact preflight the extension needs; the `moz-extension://*` predicate accepts
ANY installed extension's origin, not just this project's own. Both are defense-in-depth (CORS is
documented as NOT this API's auth boundary — every state-changing route still requires a bearer
token), but both close real gaps the v0.3 codebase sweep flagged (CODEBASE-GAPS.md Top-5 #4).

Output: `crates/pv-server/src/routes/mod.rs` with an explicit header allowlist and no wildcard origin
predicate; a new real-socket integration test proving the Firefox preflight case against a genuinely
bound server; the four Firefox e2e-firefox lanes' operator docs updated with concrete UUIDs so none
goes red after the wildcard removal.
</objective>
