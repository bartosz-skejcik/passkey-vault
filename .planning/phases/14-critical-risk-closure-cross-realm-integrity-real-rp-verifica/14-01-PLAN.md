<objective>
Close QA-03: add a real, independent-vendor `webauthn-rs` round-trip test that verifies an actual `pv-provider`-produced registration and authentication ceremony (real bytes, real signature verification) — never a shape/`.ok`/`id`-only assertion. This closes the exact fixture blind spot that hid the v0.2 `serialize_bytes_as_base64_string` byte-serialization bug (resolved in `.planning/debug/resolved/firefox-provider-corruption.md`), which was only caught because a later, unrelated debug session happened to look.

Purpose: `pv-server`'s own existing WebAuthn tests use `webauthn_authenticator_rs::softpasskey::SoftPasskey` — kanidm's OWN client/authenticator implementation, the SAME vendor as `webauthn-rs`. No test in this codebase has ever proven `pv-provider`'s (1Password-family `passkey-*`) JSON output is actually consumable by an INDEPENDENT WebAuthn implementation. This plan proves it, or reports exactly where it breaks.

Output: `crates/pv-provider/tests/real_rp_verification.rs` (new), a dev-dependency edge from `pv-provider` to `webauthn-rs` (already a pinned, pre-approved workspace dependency via `pv-server`).
</objective>
