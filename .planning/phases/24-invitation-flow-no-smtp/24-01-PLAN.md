<objective>
Lay the additive foundation the rest of Phase 24 builds on: the `invitations` table (migration 0017),
the symmetric invite-secret-derived crypto primitive in `pv-core` (FAM-04/05/06's crypto layer), an
`OptionalSessionUser` extractor `invitations::accept` will need (Plan 24-02), and the extraction of
`families::add_member`'s / `collections::add_member`'s raw INSERT logic into shared `pub(crate)`
helpers so `invitations::accept` never grows a second, parallel membership-write path
(CONTEXT.md's locked constraint #6, RESEARCH.md Pattern 2 / Pitfall 3).

Purpose: every downstream plan in this phase (server routes, pv-wasm bindings, web UI) depends on
these primitives existing and being correct — this plan produces no user-observable behavior itself,
but is the prerequisite every other plan cites.
Output: `0017_invitations.sql`, `pv_core::invite` (new module), `OptionalSessionUser` (session.rs),
two new `pub(crate)` membership-write helpers (families.rs, collections.rs).
</objective>
