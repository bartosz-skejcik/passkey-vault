<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| lib/crypto/index.ts ↔ rest of web/src | the only sanctioned crossing point for raw WASM bindings — a second import site would let key material leak into a component's own scope unaudited |
| invite URL fragment ↔ invite URL path | both derived from the same secret; a mismatch means either a tampered link or a copy/paste error — must be caught client-side before any network call |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-24-12 | Information Disclosure | web/src/lib/invite/crypto.ts | medium | mitigate | `secretBytes` is captured into `secretForUrl` (a value, not a live buffer reference) before `WasmInviteChannel.fromSecret` zeroizes it; the raw secret is never written to `localStorage`/`sessionStorage` anywhere in this module (React state ownership lands in Plan 24-06) |
| T-24-13 | Tampering | web/src/lib/invite/crypto.ts (redeemInviteFlow) | medium | mitigate | the fragment-vs-path invite_id self-consistency check runs BEFORE any network call, so a corrupted/mismatched link fails closed client-side rather than producing a confusing server round trip |
| T-24-14 | Elevation of Privilege | web/src/lib/identity/ensure.ts | medium | mitigate | the race-loser path always adopts the SERVER's canonical published key (never trusts its own locally-generated one once `adopted_existing: true` comes back), matching `identity.rs`'s own documented idempotent-upsert contract |

</threat_model>
