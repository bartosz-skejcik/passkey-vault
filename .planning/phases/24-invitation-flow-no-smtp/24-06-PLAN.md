<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| InviteLandingView's local React state ↔ localStorage/sessionStorage | inviteSecret must never cross into persistent storage — a durable copy of a decryption-capable secret would survive well past the flow's own lifetime |
| invite URL ↔ third-party navigation targets | the failure state's own `invite.failureCta` link and the "join as a different account" escape must not carry the invite_id/secret into a new navigation context in a way that could re-leak them |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-24-15 | Information Disclosure | InviteLandingView.tsx | high | mitigate | `inviteSecret` is held only in this component's own React state for its mounted lifetime; no `localStorage.setItem`/`sessionStorage.setItem` call anywhere in this file; register/login render as CHILDREN of this component (never a route change), so the state survives the sub-flow without ever needing to be persisted |
| T-24-16 | Spoofing / honesty | InviteLandingView.tsx (fingerprint block) | high | mitigate | `invite.fingerprintHonesty` copy is rendered byte-for-byte from the dictionary with no paraphrase, and there is no "mark as verified" affordance anywhere in this component (that is explicitly Phase 26 scope per CONTEXT.md's Amendment) |
| T-24-17 | Elevation of Privilege | InviteLandingView.tsx (session-exists branch) | medium | mitigate | the Join button is disabled until `useIsUnlocked()` is true, so `redeemInviteFlow` can never be invoked with a null `UserKey` and silently fail into an inconsistent partial state |

</threat_model>
