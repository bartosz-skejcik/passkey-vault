<objective>
Expose Phase 24's new `pv_core::invite` primitive through `pv-wasm` in the same opaque-handle style
Phase 21 established (`WasmWrappingKey`, `WasmCollectionKey`) — the one new WASM-crossing surface this
phase needs, since every other primitive it uses (`pv_core::identity::seal`/`unseal`,
`WasmCollectionKey`) already has bindings.

Purpose: gives Plan 24-05 (web crypto glue) a ready, tested, opaque handle to build the owner's
"generate invite" and the invitee's "redeem invite" flows on — including 24-CONTEXT.md's Amendment 2
proof-of-possession leg, so `invite_id` alone is never enough to reach the server's data.
Output: `WasmInviteChannel` (opaque handle wrapping the derived `invite_id`, `invite_wrap_key`, and
`invite_proof`) + `generateInviteSecret()` (the one place raw secret bytes legitimately cross the
boundary, since they must appear in the URL fragment itself).
</objective>
