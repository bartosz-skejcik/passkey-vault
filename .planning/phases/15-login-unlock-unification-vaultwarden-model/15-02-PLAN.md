<objective>
Build the genuinely new AUTH-04 teardown primitives — a self-contained "sign out of whatever
server is CURRENTLY configured" function — as a greenfield, independently-testable module.
RESEARCH.md confirms nothing in the current codebase invalidates an old session or revokes an
old host permission on server reconfigure: no `browser.permissions.remove()` call exists
anywhere in `extension/`, no `POST /api/auth/logout` call exists anywhere in `extension/`
despite the server route already existing, and no function clears `SessionMeta` in full.

This plan builds ONLY the teardown primitives (session-storage, auth-api, vault-session). The
server-URL-change SEQUENCING that calls them (grant-new-permission -> sign-out-old ->
persist-new-config -> revoke-old-permission) is Plan 15-05's job — `signOutVaultSession()`
itself takes no arguments and knows nothing about a "new" server; it purely tears down the
CURRENTLY-configured session, which is what makes it safely composable by a caller that
controls ordering (Pitfall 1 from RESEARCH.md: the logout POST must fire BEFORE
`configureServer(newUrl)` overwrites the persisted base URL, or it silently hits the wrong
server).

Independent of the ceremony-window work (Plan 15-01) — no shared files, can run in parallel.

Purpose: close the AUTH-04 gap with new, tested orchestration of entirely existing primitives
(server's own /logout route, browser.permissions API, existing storage helpers) — not new
crypto, not a new server endpoint.
Output: `clearSessionMeta()`, `logout()`, `signOutVaultSession()`, each independently unit
tested.
</objective>
