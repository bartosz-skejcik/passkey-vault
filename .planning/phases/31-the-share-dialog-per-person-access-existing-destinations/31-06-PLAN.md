<objective>
Close SC5's second, genuinely new refusal case — the destination-key-unavailable path that only exists once a dialog can target an EXISTING destination (the fresh-create path can never hit it, since the caller always seals their own copy at creation time). Per RESEARCH.md's own finding, this is reachable only through a narrow TOCTOU window: a concurrent revoke of the caller's OWN access to the destination between dialog-open and submit. This plan drives that window deliberately rather than leaving the failure branch untriggered.

This plan also closes Q2's own atomicity proof — not merely a final-state read (which cannot distinguish an atomic update from a client-side revoke-then-re-add producing the identical end state), but a dispatch-level assertion that exactly one `updateCollectionAccess` call fires and zero revoke/grant calls occur for the edited recipient — then performs the phase's final CI-width acceptance sweep.

Purpose: SC5 (the destination-unavailable case), Q2 (the dispatch-level atomicity proof, not just end-state), phase-wide acceptance.
Output: an honest, deliberately-triggered refusal for a lost-destination-access mid-session; a proof that a level edit takes the single-UPDATE path rather than revoke-then-re-add; a green CI-width sweep.
</objective>
