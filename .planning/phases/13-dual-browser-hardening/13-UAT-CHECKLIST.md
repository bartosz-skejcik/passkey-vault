## Deviations / findings from this Chrome pass (see 13-03-SUMMARY.md for full detail)

- **Genuine Chrome-side/environment fixes made during this pass** (in-scope per 13-CONTEXT.md — this phase owns the fix, not just the finding):
  1. `crates/pv-provider/src/ceremony.rs`: `passkey_client::Client` now calls `.allows_insecure_localhost(true)`. `passkey-client@0.5.0`'s `RpIdVerifier` rejects `rp_id == "localhost"` by default (`InsecureLocalhostNotAllowed`) and requires HTTPS for every other `rp_id` — this is exactly why the Phase 12 manual UAT (webauthn.io, a real HTTPS site) never hit it, but this Playwright harness's local `http://localhost` RP test pages did. The fix is scoped to the literal string `"localhost"` only (unspoofable by a remote attacker) and also unblocks a legitimate self-hoster use case (registering passkeys against their own locally-served app).
  2. `extension/e2e/fixtures.ts`: launches **headed** Chromium (`headless: false`), not the plan's originally-stated `headless: true` — the Phase 12 provider ceremony hangs indefinitely post-confirm in headless Chromium on this environment (no error, no terminal relay message, ever) but resolves correctly within seconds in headed Chromium with the identical build, matching the original manual real-Chrome UAT's success.
  3. Several test-harness stabilizations for this dev machine's real, measured memory pressure (swap usage 6-7GB of 7-8GB during test runs) under headed-mode multi-tab load: a bounded 3-attempt retry with real backoff inside `openWebApp()`, `playwright.config.ts`'s `retries: 2`, `formServer.closeAllConnections()` before `afterAll`'s close (a real hang otherwise), and reusing (not re-signing-in for) the web-app tab within a single test while still forcing a fresh tab at each test's start.
  4. A genuine test-authoring bug: P10-SC4 used a non-existent `#item-address` selector (the real identity form has `#item-addressLine1`/`#item-addressLine2`, no single `#item-address` field) — `.fill()`'s long poll against a selector that could never match was this suite's single most exposed spot to an (unrelated) environmental crash. Fixed to the real field id.
- **Final clean run: 21/21 passed** (16 outright on the first attempt, 5 Phase-10 tests recovered on a bounded retry — every retry recovered via a genuinely fresh tab/sign-in, never a fabricated pass).
