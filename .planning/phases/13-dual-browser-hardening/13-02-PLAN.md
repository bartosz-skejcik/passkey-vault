<objective>
Give Firefox's PRF gap an explicit, legible, honest UI state (D-03) wherever the extension offers a passkey fast-path: the popup unlock screen (Phase 9) and the passkey-provider ceremony consent card (Phase 12). Detection reads the actual WebAuthn ceremony's `clientExtensionResults.prf.enabled` at attempt time — never user-agent sniffing — since PRF availability is per-credential/per-OS, not purely per-browser (D-06 invariant: PRF must never become a hard requirement).

Purpose: ROADMAP Phase 13 SC #3 — "wherever Firefox lacks a capability... the UI communicates it explicitly instead of silently failing or degrading." This is the one genuinely new piece of UI code this phase owns (13-UI-SPEC.md's "capability-degradation contract").
Output: A shared, unit-tested PRF feature-detection module, wired into both surfaces that offer a passkey fast-path, using the exact PL/EN copy from 13-UI-SPEC.md.
</objective>
