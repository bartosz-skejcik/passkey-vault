  <action>
    Add `@playwright/test` as a devDependency (`npm i -D @playwright/test`; `npx playwright install
    chromium` — Firefox is intentionally NOT installed for Playwright here, see rationale below).
    Before installing, run `npm view @playwright/test repository.url` as an automated sanity
    re-confirmation — 13-RESEARCH.md's Package Legitimacy Audit already approved this package
    (Microsoft-official, 42M+ weekly downloads); no blocking checkpoint required.

    Playwright's extension-testing support is Chromium-only: loading an unpacked/built extension
    requires `chromium.launchPersistentContext(userDataDir, { args:
    ['--disable-extensions-except=<path-to-.output/chrome-mv3>',
    '--load-extension=<path-to-.output/chrome-mv3>'] })` — Playwright does not support loading a
    WebExtension into its Firefox or WebKit channels. This is why Firefox's pass is a separate
    mechanism in Plan 13-04, not a `firefox` project in this same Playwright config. Write
    `extension/playwright.config.ts` with a single `chromium` project using this persistent-context
    pattern, pointed at the actual `.output/chrome-mv3` (or whatever Phase 8 actually named it —
    confirm via `ls extension/.output/`) directory produced by `npm run build` (or `wxt build -b
    chrome`).

    In `extension/e2e/dual-browser.spec.ts`, write one test case per success criterion from Phases
    9-12 (19 total: Phase 9's 5, Phase 10's 5, Phase 11's 4, Phase 12's 5 — copy the exact SC wording
    from ROADMAP.md, do not paraphrase, so the mapping to the checklist is unambiguous). Group tests
    by phase using `test.describe()` blocks. Where a test exercises a WebAuthn ceremony (Phase 12's
    passkey-provider SCs), use Playwright's Chrome DevTools Protocol WebAuthn virtual authenticator
    (`page.context().newCDPSession(page)` + the `WebAuthn.enable`/`addVirtualAuthenticator` CDP
    commands) to simulate a passkey without real hardware — set `hasPrf: true` on the virtual
    authenticator for the PRF-available test cases, and `hasPrf: false` (or omit the extension) for
    the PRF-unavailable-on-Chrome edge case, so the D-03 banner logic gets exercised even on Chrome
    in cases where a specific authenticator genuinely lacks PRF support. Add a
    `"test:e2e:chrome": "playwright test --project=chromium"` script to `extension/package.json`.
  </action>
