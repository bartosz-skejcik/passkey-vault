<objective>
Wire the client half of SYNC-06's attribution (server half closed in Plan 23-03) and give
`web/src/lib/vault/sync.ts` a real, working call to the new `GET /api/sync/shared` revisions-map
endpoint (Plan 23-02) on every pull cycle — the concrete client-engine plumbing SEC-08's Playwright
proof (Plan 23-06) exercises over the network. Per CONTEXT.md's confirmed research finding: both
existing WS consumers (web and extension) already treat "any frame" as "go pull" with zero payload
parsing, so `EntityType::Collection` needs no client-side WS-frame-parsing change — only `pullOnce`
itself gains a second outbound call.

Scope boundary (documented rationale, since this deviates from a literal reading of "shared items
render in the vault"): decrypting and rendering a COLLECTION-scoped item, or a directly-shared item
from the RECIPIENT'S OWN perspective, both require an unwrapped `IdentitySecretKey` the client does
not yet generate — that trigger is explicitly Phase 26's job (KEY-01 client-trigger, ROADMAP.md Phase
26 SC5), not this phase's. `packages/pv-ui/vault/types.ts`'s `VaultItem` therefore gains
`isShared`/`lastEditorEmail` as METADATA fields only (sourced from server-side columns, never from
ciphertext), populated on the EXISTING personal `/api/sync`/`/api/vault/items` responses an item's own
owner already receives and already decrypts today — this is what makes SYNC-06's attribution provable
this phase without waiting on Phase 26: the owner of a shared item, viewing their OWN item in
DetailPanel, sees an attributed conflict banner the moment a co-editor (added via raw API in Plan
23-06's Playwright fixture, or later via Phase 26's real sharing UI) edits it concurrently. The full
shared-collection-browsing UI remains Phase 26's, per CONTEXT.md's explicit "Sharing UI... -> Phase
26" boundary.

Purpose: give SYNC-06 a real, wired, testable client half; give the Playwright harness (Plan 23-04)
something concrete to observe over the network for the "revision fan-out" / "conflict attribution"
proofs Plan 23-06 writes.
Output: `ApiClientError.details`; `VaultItem.isShared`/`lastEditorEmail`; `sync.ts`'s shared-revisions
pull; `RevisionConflictError.lastEditorEmail`; both DetailPanel banners rendering attributed copy;
new PL+EN dictionary keys.
</objective>
