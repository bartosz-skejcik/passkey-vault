<objective>
Stand up SEC-08's second layer — a brand-new Playwright harness in `web/`, which has zero e2e
infrastructure today (verified: the only Playwright config in this repo is
`extension/playwright.config.ts`, and its `launchPersistentContext`/`--load-extension` mechanism is
Chromium-extension-specific and not reusable here). This is genuinely new infrastructure, built
independently of the server-side sync work (Plans 23-01/23-02/23-03) and the client sync-engine
wiring (Plan 23-05) — a smoke spec proves the harness itself (bring-up, two independent sessions, a
real server) before Plan 23-06 builds the actual shared-sync proof specs on top of it.

Per CONTEXT.md's locked constraints: two sessions means two independent `browser.newContext()`
calls, never a shared context with a swapped token. Zero OS-level dialogs — every fixture
authenticates via the web app's own password-only `LoginForm.tsx`/`RegisterForm.tsx` flow, never the
real WebAuthn ceremony (Phase 20's standing "no OS dialogs in automation" rule). Server lifecycle via
Playwright's own `webServer` config, against a real `pv-server` on a throwaway SQLite DB, built with
`NEXT_PUBLIC_API_BASE_URL=""` — routing around, never touching, the documented
`web/.env.local`/`localhost:8620` same-origin footgun already on record in STATE.md's Blockers
section.

Purpose: convert SEC-08's requirement — "a live multi-session test harness... exists" — into standing,
runnable infrastructure, matching the milestone's own v0.2->v0.3 lesson that a manual "verified live
in 2 tabs" ritual is not a substitute for automation.
Output: `web/playwright.config.ts`, `web/e2e/fixtures.ts`, `web/e2e/smoke.spec.ts`, and a `test:e2e`
npm script.
</objective>
