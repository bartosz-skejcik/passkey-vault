# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Generated overnight in fully autonomous mode** (Bartek asleep, explicit standing authorization — see 06-CONTEXT.md header). Every visual-taste call this agent had to make without a human in the loop is called out in **Morning review notes** at the end of this document. Nothing security-adjacent was left ambiguous: the export plaintext-warning dialog and the TOTP live-code surfaces follow the same "sober, never playful" rule Phase 2/3 already locked for the delete-confirm dialog and unlock overlay — this phase's one genuinely playful surface (the onboarding wizard's chrome) is explicitly firewalled from bleeding into the sober `ImportWizard` it embeds (see "Sober/playful boundary" below).

## Design System

| Property | Value |
|----------|-------|
| Tool | none — carried forward unchanged from Phase 1–3. `components.json` confirmed absent. This phase's most complex new surface (`ImportWizard`'s multi-step file→preview→mapping→progress flow) is a linear state machine over the *existing* modal-overlay pattern (`fixed inset-0 z-50` + `bg-base-300/70` scrim, same shape as `DeleteConfirmDialog.tsx`/`EnrollPasskeyDialog.tsx`) — no Radix primitive (focus trap, combobox, data-table) is needed that DaisyUI's native `<dialog>`-backed `modal`/`table`/`collapse` don't already cover. **Not re-asked of the user — standing project decision.** |
| Preset | not applicable |
| Component library | DaisyUI 5. New component classes entering the app this phase: `radial-progress` (TOTP countdown ring — list row + detail panel), `file-input`/`file-input-bordered` (import file picker), `progress`/`progress-primary` (import execution progress bar), `table`/`table-zebra table-sm` (import preview + manual column-mapping grid — used only inside the wide 640px `ImportWizard` modal, never squeezed into the 400px Settings drawer), `collapse`/`collapse-arrow` (manual TOTP-add "Advanced" fields toggle; import summary's expandable skipped-reasons list), `alert alert-warning` (export plaintext-warning body — a deliberate, documented new register, see Color section). Reuses unchanged: `modal`-shape overlay (`fixed inset-0 z-50` + scrim) for both `ImportWizard` and `ExportDialog`, `btn-primary`/`btn-ghost`/`btn-error`/`btn-warning`, the neutral-icon-in-32px-slot item-type-row pattern (no badge pill — matches shipped `ItemRow.tsx`, not the older per-spec-text "badge pill" description), `tabs tabs-bordered` (Settings panel, unchanged from Phase 3), `dropdown` (unchanged). |
| Icon library | `lucide-react` (carried forward, already installed — no new dependency). New icons this phase: `Timer` (TOTP item-type icon — one new icon, distinct from `KeyRound`-teal-passkey and `ShieldCheck`-Security-tab meanings, reads as "time-based code" per the established one-icon-one-meaning discipline), `Upload` (import trigger + dropzone icon — same icon at both the Settings-tab CTA and the dropzone itself, one meaning), `Download` (export trigger), `FileWarning` (unrecognized-format / row-skip-reason iconography — distinct from `AlertTriangle`, which stays reserved for destructive/blocking states per Phase 2/3's usage), `CircleCheck` (import-done / onboarding-finish completion icon — success-green, distinct from the small inline `Check` already used for copy-confirm flashes), `ArrowRight` (onboarding "Dalej"/Next button). No new icon-library dependency; every icon ships in the already-installed `lucide-react` package. |
| Font | Unchanged: `DM Sans` for all UI text; `Fuzzy Bubbles` stays confined to the vault empty-state and, **new this phase**, the onboarding wizard's own chrome (headings/orientation copy/finish screen) per `docs/UI-DESIGN.md` §1's explicit onboarding carve-out. **Hard boundary, not a suggestion:** the `ImportWizard` component is byte-for-byte the same component whether it's mounted inside onboarding's Step 1 or opened from the sober Settings → Import/Eksport tab — it is **always** plain DM Sans, no Fuzzy Bubbles, no emoji, regardless of which shell embeds it (06-CONTEXT.md's explicit "must not bleed into each other" instruction). The `ExportDialog` plaintext-warning and every TOTP live-code surface (list row + detail panel) are likewise always plain DM Sans — TOTP codes and export warnings are security-relevant values, held to the same sober standard as the unlock overlay and delete dialogs. `ui-monospace` extends to: the TOTP live code (both row and detail-panel sizes), the TOTP secret field (manual-add input + detail-panel masked/revealable value), and the otpauth-URI paste field. |

|-------|-------|-------|

| sm | 8px | Compact spacing, step-dot gap, mapping-table cell padding |
| md | 16px | Default element spacing, import/export dialog internal padding, onboarding card padding (mobile) |
| lg | 24px | Section padding within panels/dialogs (`ImportWizard`/`ExportDialog` body padding, onboarding card padding desktop) |
| xl | 32px | Onboarding takeover's vertical breathing room above/below the content card |
| 2xl | 48px | Major section breaks (space between the import-preview table and its action row) |
| 3xl | 64px | (unused this phase) |

**Fixed layout dimensions this phase (all multiples of 4/8, not new tokens beyond the two explicitly justified below):**

| Element | Value |
|---|---|
| **Import wizard modal width** | **640px — new, wider than the established 400px dialog/panel vocabulary.** Justified exception: the preview table and manual column-mapping grid need real horizontal room for 5+ columns; a 400px width (Phase 2/3's dialog/drawer standard) would force horizontal scrolling on the wizard's most important screen. Used identically at **both** call sites — the Settings → Import/Eksport tab's "Zaimportuj hasła" CTA opens this same 640px modal (it does **not** render the wizard squeezed inline into the 400px Settings drawer). |
| Export dialog width | 400px — unchanged, reuses `DeleteConfirmDialog`'s exact width/shape/border/radius vocabulary verbatim. |
| **Onboarding takeover content card width** | **640px cap, uniform across all 3 steps.** Step 1 needs the room for the embedded `ImportWizard`; Steps 2/3 render narrower, centered content within that same cap rather than jumping to a different card width mid-flow — one width vocabulary for the whole wizard, not three. |
| TOTP list-row countdown ring | 24px diameter (`radial-progress`, `--size: 1.5rem; --thickness: 3px`) |
| TOTP detail-panel countdown ring | 64px diameter (`--size: 4rem; --thickness: 4px`) — one visual step above the 32px row-icon vocabulary, matching `docs/UI-DESIGN.md` §2's own "hero-liczby... oversized" allowance for security-relevant numbers (security score, item counts) |
| Import preview/mapping table row height | 48px — denser than the 64px vault-list row; this is a scannable data-review grid, not a primary navigation list |
| Import dropzone min-height | 160px — generous drop target, standard file-upload UX practice |
| Step-dot diameter | 8px (= `xs` token), 8px (= `sm` token) gap between dots |

**Exception — icon-only touch targets:** reuses Phase 2's pre-approved 40px hit-area exception verbatim for every icon-only button introduced this phase (TOTP copy buttons, import-wizard close, collapse toggles where icon-only) — no new exception category opened.

Unchanged from Phase 1–3 — 4 sizes, 2 weights. Carried forward, not re-opened:

| Label | 14px | 400 | 1.4 |
| Body | 16px | 400 | 1.5 |
| Heading | 20px | 700 | 1.2 |
| Display | 28px | 700 | 1.15 |

- Body → TOTP detail-panel issuer subtitle, import/export tab body copy (Settings), dialog body copy (export warning, import summary, mapping instructions), onboarding step body copy.

No new size, no new weight. Emphasis (current onboarding step, active mapping-table row) comes from color/fill exactly as Phase 2/3 established — never a third weight.

## Color

Unchanged 60/30/10 split and hex/OKLCH values from Phase 1–3 (`vault-dark` default, full `vault-light` parity). This phase activates one previously-narrow token (warning) into a new register and introduces no new hue.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#1F1F1F` base-300 dark | Onboarding takeover scrim/canvas, page canvas behind Settings drawer |
| Secondary (30%) | `#262626` base-100 (dialogs, panels, rows) + `#212121` base-200 (row hover, mapping-table zebra stripe) | `ImportWizard`/`ExportDialog` surfaces, onboarding content card, TOTP row/detail backgrounds |
| Accent (10%, coral `#E16540`) | primary | "Zaimportuj hasła"/"Eksportuj vault" CTAs (Settings tab), `ImportWizard`'s "Importuj {n} pozycji" execute button + progress-bar fill, onboarding's "Dalej"/"Przejdź do vaulta" CTAs, onboarding step-dot current/completed fill, **TOTP detail-panel countdown ring (both sizes) — locked directly by `docs/UI-DESIGN.md` §3.3's literal "pierścień w kolorze koralowym"** |
| Destructive | `#FF5861` error | **Not used anywhere new this phase.** No delete/destroy action exists in Phase 6's scope — reserved exactly as Phase 2/3 left it (item/passkey/session delete confirms only). |

Accent (coral) reserved for the elements listed above only — **never** for the TOTP item-type icon (stays neutral, see below), skipped-row indicators, or any decorative fill.

**Warning (`#FFBE00`) — new, deliberate expansion of an existing token into a new register this phase:**
- **`ExportDialog`'s icon + `alert-warning` banner + confirm button (`btn-warning`, "Pobierz mimo to") — NOT `btn-error`/error-red.** This is a considered departure from literally copy-pasting `DeleteConfirmDialog`'s red `AlertTriangle`/`btn-error` treatment: 06-CONTEXT.md says to reuse its *sober security-UI treatment* (plain DM Sans, `AlertTriangle` icon, 400px modal, Cancel/Confirm row, `alert alert-*` banner) — the **structural** pattern, not necessarily its literal color. Nothing is being destroyed by an export; the risk is plaintext leaving the app, a "proceed with caution" action, which `docs/UI-DESIGN.md`'s own color table maps to warning ("hasło stare/powtórzone" — attention-worthy, not destroyed) rather than error ("wyciek, słabe hasło" — an actual problem). Flagged under Morning review notes as a taste/semantics call worth a second look, not a structural risk.
- Import summary's "N pominięto"/"N skipped" count — warning-colored text/badge, not error-red (a skipped row is non-fatal and expected, not a failure of the import itself).

**Success (`#00A96E`)** → import-done `CircleCheck` icon, onboarding Step 3's completion icon — reused exactly as Phase 2/3 used it, a completion signal, never a CTA color.

**TOTP item-type icon (`Timer`) stays neutral, matching the shipped `ItemRow.tsx` icon-in-32px-slot pattern exactly** — `text-base-content/70` on `bg-base-200`, identical treatment to `Vault`/`CreditCard`/`IdCard`/`StickyNote`. **Not** coral, **not** teal — teal stays exclusively reserved for passkey/PRF meaning (Phase 2/3's locked rule, reaffirmed, not reopened). The coral ring is the *only* accent color a TOTP item ever shows, and only in the live-code countdown itself, never on the row/type icon.

## Phase-Specific Notes

### TOTP as a first-class item type (VAULT-07)

- **List row (`ItemRow.tsx`):** `Timer` icon in the existing 32px neutral icon slot (same treatment as `Vault`/`CreditCard`/`IdCard`/`StickyNote` — no badge pill, matches shipped code, not the older spec-text description). Subtitle line = `issuer` if present, else the `itemType.totp` label (mirrors how `username` differentiates a login row). **The row's trailing content area — currently occupied by the relative-updated-time text — is replaced for `totp` items specifically** by: mono live code (Label/14px) + 24px coral `radial-progress` ring + a hover-revealed copy icon-button (40px hit area, same reveal convention as the row's kebab-menu trigger). The relative-time timestamp is dropped for TOTP rows only — the live code is strictly more actionable information in that slot than "updated 3 days ago."
- **Detail panel (`DetailPanel.tsx`):** needs a bespoke TOTP branch, analogous to the existing `item.fields.type === "login" ? <PasskeyPlaceholderSection /> : null` pattern — `algorithm`/`digits`/`period` don't fit the generic Label+value field loop (per 06-RESEARCH.md Pattern 2). Layout, header row (name as Heading) unchanged, then:
  1. Issuer subtitle line directly below the header (Label, `base-content/60`) — not a copy-able field row, matching how a login's username differentiates without its own field row.
  2. A centered bespoke block: 64px coral `radial-progress` ring with the Display-size (28px/700) mono code inside/beside it, a small numeric seconds-remaining caption, and a copy icon-button next to the code — reuses `copyWithAutoClear`/`readClipboardSeconds`/`showCopyToast` exactly like every other field's copy button (**not a new clipboard mechanism**). Note for the executor: the clipboard-clear window (30–60s, default 40s) can outlast a single TOTP period (30s default) — the clipboard may still hold an already-expired code when it clears. This is expected, matches how every TOTP app behaves, and is **not** a bug to special-case by shortening clear time for TOTP specifically.
  3. `secret` rendered via the **existing generic FIELD_ORDER loop** (`FIELD_ORDER.totp = ["secret"]`) — masked by default, revealable (`Eye`/`EyeOff`), copyable, mono — this is a straight extension of the already-generic mask/reveal/copy pattern `password`/`number` use today, zero new interaction vocabulary. Including a viewable/copyable raw secret is a deliberate completeness decision (lets a user re-provision the same TOTP secret to another device) — low-risk, mechanical, not flagged for morning review.
  4. `algorithm`/`digits`/`period` are **never shown in view mode** — RFC 6238 defaults stay invisible plumbing unless the source data set them non-default; only exposed in the create/edit form's collapsed Advanced toggle (next).
  5. Folder/tags sections below, unchanged — already generic across every item type.
- **Manual-add form (`ItemForm.tsx`):** `emptyFieldsFor("totp")` returns RFC 6238 defaults (`algorithm: "SHA1", digits: 6, period: 30`). Required visible field: `secret` (mono input, `totp.secretHelper` placeholder text). If the pasted value starts with `otpauth://`, auto-parse it client-side (06-RESEARCH.md Pattern 4's `parseTotpValue`) and populate `issuer`/`algorithm`/`digits`/`period` from the URI — the Advanced `collapse` stays closed even when auto-populated (the user pasted a link, they don't need to see the parsed-out internals unless they open it). `algorithm`/`digits`/`period` live inside a `collapse collapse-arrow` labeled `totp.advancedToggle`, **default closed** (06-CONTEXT.md's Claude's-Discretion leaning, now locked). Invalid/unparseable secrets surface `totp.invalidSecretError` inline (red `text-error`, matching the codebase's existing form-validation-error convention) — never silently accepted.
- `TotpCountdownRing.tsx` (per 06-RESEARCH.md's recommended structure) is a single component parameterized by size (24px row / 64px detail), used at both call sites — one ring implementation, not two.

### Import wizard (IMPEX-01/02/03, UI-04 step 1)

`ImportWizard.tsx` is one component, mounted from two call sites (Settings → Import/Eksport tab's CTA, and onboarding Step 1) — both render the **identical** 640px modal (`fixed inset-0 z-50` + `bg-base-300/70` scrim, same shape/border/radius vocabulary as `DeleteConfirmDialog`/`EnrollPasskeyDialog`, just wider). No stripped-down subset inside onboarding (06-CONTEXT.md's explicit instruction).

- **Screen 1 — file select:** dropzone (`file-input file-input-bordered`, 160px min-height, `Upload` icon, `import.dropzoneLabel`/`import.dropzoneHint`). `import.skip` (ghost text button, low visual weight, top-right of this screen only — **not present on any later screen**, per 06-CONTEXT.md's "Skip is available at the file-select screen only" rule).
- **Screen 2a — format detected:** brief `import.formatDetected` confirmation line, auto-advances to preview (no extra click needed when detection succeeds).
- **Screen 2b — format unknown → manual mapping:** `import.mappingTitle`/`import.mappingHint`, a `table table-sm` with one row per required field (`name`, `username`, `password`, `urls`, `notes`, etc. depending on inferred rough shape) and a `<select>` per row listing the file's actual column headers — this **is** IMPEX-03's generic path, not a separate screen from IMPEX-01/02's per-tool mappers (same UI, populated differently).
- **Screen 3 — preview:** `table table-zebra table-sm`, 48px row height, `import.previewTitle`, one row per parsed item (name/type/username-or-issuer columns), `import.previewEmpty` state if zero rows parsed. `import.startButton` (coral, primary) begins the write loop; `import.back`/`import.cancel` available.
- **Screen 4 — progress:** `progress progress-primary` bar + `import.progressLabel` live count, no cancel mid-loop (see dismissal rule below).
- **Screen 5 — summary:** `import.summaryTitle` + (`import.summaryAllOk` or `import.summaryBody` with warning-colored skip count), `import.skippedReasonsToggle` (`collapse collapse-arrow`) expands a plain list of `{itemName/rowIndex}: {reason}` using the `import.reason*` strings — never a silent partial success. `import.done` closes the wizard (Settings context) or advances onboarding to Step 2 (onboarding context) — same button, different `onClose` wiring per call site, not a UI difference.
- **Dismissal rule (mirrors Phase 3's enrollment-ceremony precedent):** the modal is **not** dismissible via click-outside/`Esc`/close-icon while Screen 4 (the encrypt+POST loop) is actively running — an app-level accidental-dismiss mid-write would desync the in-flight per-item writes from the UI. Dismissible at every other screen via a top-right `X` (reusing `aria.closePanel`) plus the explicit `import.cancel` button.
- Row-level fault tolerance (06-CONTEXT.md, locked): a malformed/oversized row never aborts the loop — it's counted and reported in the summary's expandable reason list.

### Export dialog (IMPEX-04)

`ExportDialog.tsx`, 400px, same modal shape as `DeleteConfirmDialog` exactly — width, border, radius, Cancel/Confirm row layout are a **direct visual copy**; only the icon/banner/confirm-button color differ (warning, not error — see Color section's reasoning). Contents top-to-bottom: format choice (`JSON`/`CSV` — a simple two-option toggle, e.g. `join`-style segmented buttons or radio pair, planner's exact control choice), `AlertTriangle` icon (warning color) + `export.warningTitle` (Heading), `alert alert-warning` banner with `export.warningBody` (states plaintext exposure + the passkeys-not-exported fact explicitly, per 06-CONTEXT.md), `export.cancel` (`btn-ghost`) / `export.confirm` (`btn-warning`, "Pobierz mimo to").
