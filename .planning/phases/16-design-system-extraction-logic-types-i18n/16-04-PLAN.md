<objective>
Extract the i18n engine (`t`, `interpolate`, `Locale`, `resolveLocale`) into
`packages/pv-ui/i18n/engine.ts` and split the two consumer dictionaries into a shared
`common.ts` (34 verified byte-identical keys) plus per-surface-only entries. This is the one
place in the phase that writes genuinely NEW code rather than moving existing code: today's
`t(locale, key)` closes over each file's own module-scoped `DICTIONARY` constant and is NOT
generic — a shared engine needs `t<D>(dict, locale, key)` plus a thin, signature-preserving
per-consumer wrapper so none of the ~97 existing `t(locale, key)` call sites across both consumers
need to change.

Dictionary key overlap was re-measured directly against the live tree at planning time (not
trusted from the commissioned research's pre-Phase-15 snapshot, per CONTEXT.md's own drift
warning): of 38 keys sharing an exact key name between web's and extension's `DICTIONARY` objects,
34 are byte-identical and 4 have genuinely different PL/EN copy (`vault.emptyHeading`,
`vault.emptyBody`, `search.emptyResults`, `autolock.label`) -- these 4 numbers are unchanged from
the commissioned research despite Phase 15 landing 370->301 lines of unrelated edits to
extension/lib/i18n/dictionary.ts in between, confirmed by a fresh key-by-key diff run during this
planning session. The 4 divergent keys must stay local-only to each consumer or one surface's live
UI copy silently changes -- a regression this phase's own success criteria explicitly forbid.

`dictionary.ts` and `autofill-dictionary.ts` have zero imports from `vault/types.ts` or any other
migrated module in this phase, so this plan has no dependency beyond the Wave-1 config plan and
runs fully in parallel with Plans 16-02 and 16-03, sharing no files with either.

Purpose: close DS-02 end-to-end -- one shared engine, dictionary keys split with zero copy drift.
Output: `packages/pv-ui/i18n/engine.ts`, `packages/pv-ui/i18n/common.ts`; both consumers'
`dictionary.ts` refactored to thin wrappers; `extension/lib/i18n/autofill-dictionary.ts` importing
`interpolate`/`Locale` directly from the shared engine.
</objective>
