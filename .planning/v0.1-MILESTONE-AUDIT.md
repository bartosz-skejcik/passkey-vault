## Cross-Phase Integration (gsd-integration-checker, Opus)

**All connections WIRED. No orphans, no missing links.** The WASM boundary invariant holds
(only `web/src/lib/crypto/` imports `pv_wasm`). Every server route has a matching client
consumer with a field-for-field wire shape.

### E2E flows — all COMPLETE
1. **Register → onboarding takeover → vault CRUD → ciphertext.** Onboarding fires only from
   `RegisterForm.onAuthed` (never login), gated by the per-browser flag; vault stores only
   `enc_key`/`enc_data` blobs. Zero-knowledge preserved.
2. **Enroll PRF → passkey login + PRF unlock → decrypt** (highest-risk seam, verified sound):
   domain constant `pv:prf-unlock:v1` is single-sourced; the PRF salt is generated once at
   `register_start`, stored, and returned identically by both `unlock_start` and
   `passkey_login_start` → identical wrapping key → `unwrapUserKey` succeeds.
3. **Import Bitwarden+TOTP → live ring → sync → JSON export.** TOTP field shape identical
   across importer/form/ring/exporter; JSON round-trip lossless.
4. **Concurrent edit → 409, no lost update.** Client sends the *baseline* revision captured
   at edit-open (CR-01 fix live) → server `WHERE revision=?` fires `Conflict` → banner, no
   optimistic overwrite.
5. **Single-container serve + fail-fast + WS-token log stripping.** Dockerfile serves
   `web/out` + API on one port with same-origin client defaults; `Config::validate()` runs
   before serve; nginx/Caddy configs strip `?token=` from `/api/sync/ws` access logs
   (closes Phase-5 WR-02 on the proxy side).
