<objective>
Reconcile `types.ts` between web (canonical superset) and extension (lagging subset) by moving
web's file verbatim into `packages/pv-ui/vault/types.ts` and converting both consumers into
`export *` shims. This is the one migration in the phase where the two sides are not already
byte-identical — web has 11 extra lines (optional `CardFields.pin`/`zip`, structured
`IdentityFields` address fields) that RESEARCH confirmed are additive-only and safe to adopt,
because `extension/lib/autofill/fill-dom.ts`'s only `IdentityFields` read is the pre-existing
legacy flat `address` field. This plan re-verifies that claim directly (grep + git-diff), not by
trusting RESEARCH's prior measurement.

`types.ts` is a leaf module (zero imports) but both `search.ts` and `sort.ts` (Plan 16-05) import
`VaultItem`/`ItemFields`/`VaultFilter` from it — so this plan must land before Plan 16-05's pv-ui
modules can resolve their own local `./types` import inside `packages/pv-ui/vault/`. That is the
sole reason Plan 16-05 is Wave 3, depending on this plan, while this plan itself is Wave 2 with
only the Wave-1 config plan as a dependency.

Purpose: close the largest single-file divergence in DS-01's duplication inventory and unblock
Plan 16-05's own migration.
Output: `packages/pv-ui/vault/types.ts` (canonical superset); both consumers' `types.ts` reduced to
1-statement shims; extension's `fill-dom.ts` proven untouched.
</objective>
