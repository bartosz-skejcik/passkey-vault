<objective>
Render the XBR-03 decision-gate verdict: a genuine, evidence-driven security review of whether a
closed-shadow-DOM in-page consent panel could safely replace the Firefox consent window, per
18-CONTEXT.md's conservative policy (D-01: anything short of an unambiguous clear closes as
REJECT-WITH-REASON with the window model standing). This plan writes NO panel code — its only
deliverable is the review artifact and the mirrored project decision record.

Purpose: Phase 12's SECURED audit closed T-12-14 ("in-page fake consent phish... structurally
unspoofable") specifically because consent renders only in an OS-level browser-chrome window,
architecturally outside the page's DOM/CSSOM. 18-RESEARCH.md assembled the evidence a reviewer
needs to honestly re-examine that boundary — most load-bearing: the August 2025 "DOM-based
Extension Clickjacking" research (Marek Toth, DEF CON 33), which found closed shadow-root gave
only PARTIAL protection against opacity/z-index/focus() manipulation in 11 major password
managers including 1Password and Bitwarden, both cited by name in this project's own code
comments. This plan's task performs that analysis for real — not a foregone rejection restated,
a genuine evaluation whose conservative-policy DEFAULT (on anything short of unambiguous clear)
happens to be rejection.

Artifacts this phase produces (this plan's share, MANDATORY per downstream_consumer):
18-SECURITY.md (new, the XBR-03 verdict artifact) and one new .planning/PROJECT.md Key
Decisions row. The remaining three mandatory artifacts (probe-window-geometry.cjs, its npm
script pair, the new unit test case) belong to this phase's sibling plan (18-01-PLAN.md, UX-02).

Output: 18-SECURITY.md with an explicit, evidence-cited SHIP or REJECT-WITH-REASON disposition,
and a PROJECT.md Key Decisions entry mirroring it.
