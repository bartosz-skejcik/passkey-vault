<objective>
Wire Plan 15-02's teardown primitives into `ServerConfigView.tsx`'s submit flow: detect when a
server switch would abandon a live session or host permission, show an explicit confirmation
dialog (AUTH-04, UI-SPEC's warning-tier deviation from the codebase's usual delete-confirm
convention — a server switch is reversible), and sequence the actual migration so the user can
never end up with zero working origins.

The hard sequencing problem: `server-config.ts`'s existing `configureServer()` (used by the
`config.set` message) both PROBES and PERSISTS the new URL in one step. Persisting the new URL
before tearing down the old session would make `logout()`'s `apiFetch` hit the WRONG server
(Pitfall 1, RESEARCH.md). This plan adds a new `config.probe` message (thin wrapper over
`server-config.ts`'s already-exported, persist-free `probeServerHealthDetailed()`) so
reachability can be validated BEFORE any persistence, keeping the OLD config live for the
teardown step.

Purpose: close AUTH-04 with new sequencing of existing primitives — no new crypto, no new
server endpoint (the /logout route already exists; Plan 15-02 already wired it).
Output: `ServerConfigView.tsx`'s confirm dialog + sequencing, `config.probe`/`session.signOut`
message kinds.
</objective>
