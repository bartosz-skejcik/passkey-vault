<objective>
Re-layout the popup's auth surfaces per 15-UI-SPEC.md, now that Plan 15-01 has proven the
ceremony window carries full sign-in (password + passkey): replace the signed-out
email/password form with a minimal hero (`SignInView.tsx`, new), and rewrite `UnlockView.tsx`
to be password-first / unlock-only with the passkey button promoted to its final `btn-accent`
treatment. This is where the popup's own sign-in form stops existing — safe now because Plan
15-01 already proved the window-based replacement works, satisfying the phase's "never a
commit point with zero sign-in paths" constraint.

This plan does NOT delete the underlying ext-scoped PRF files or router.ts kinds — it stops
CALLING them. Plan 15-04 (Wave 3, depends on this plan) deletes the now-dead files and narrows
the SessionStatus type; sequencing it after this plan avoids a circular type-coupling problem
(SessionStatus's extPasskeyEnrolled/extPasskeyPromptSuppressed fields cannot be safely narrowed
in the same wave a consumer still constructs literals against the wider type).

Purpose: land the UI-SPEC's target auth layout on both auth surfaces.
Output: `SignInView.tsx` (new), `UnlockView.tsx` (rewritten), `App.tsx` (wired to both,
enroll-prompt slot removed), `dictionary.ts` (stale `unlock.serverCeremonySigninFailed` copy
fixed only — the 3 AUTH-04 confirm-dialog keys Plan 15-05 needs are produced by Plan 15-02's
Task 1, wave 1, per revision fix, so this plan's `dictionary.ts` edit and 15-02's never race).
</objective>
