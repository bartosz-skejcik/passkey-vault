<objective>
Bridge `pv-core`'s existing crypto (Argon2id KDF, HKDF, XChaCha20-Poly1305 wrap/unwrap, per-item AEAD) to WASM through a new thin `pv-wasm` crate, and give the repo a reproducible, version-pinned build script that compiles it. This is the foundation the browser-side self-test (plan 01-03) will call into — nothing in the web app can be real until this crate compiles to `wasm32-unknown-unknown` and its round-trip is proven correct natively.

Purpose: Establish the zero-knowledge crypto choke point (`pv-wasm`) with opaque-handle key material, per CONTEXT.md's locked WASM Boundary decisions, before any UI code exists to consume it.
Output: `crates/pv-wasm` (compiles native + wasm32), `scripts/build-wasm.sh` (reproducible build, single-sourced version pin, getrandom duplicate-major audit), a small `pv-core` addition (`random_bytes`).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| WASM linear memory ↔ JS heap | The `wasm-bindgen` FFI boundary — every `pv-wasm` public function is a crossing point where secret material could leak as an unzeroizable JS-heap copy |
| Local build ↔ crates.io (`wasm-bindgen-cli` install) | Supply-chain trust for the CLI tool the build script installs |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-------------------|
| T-01-01 | Information Disclosure | `crates/pv-wasm/src/lib.rs` public API | high | mitigate | Every function operating on key material (`WasmWrappingKey`, `WasmUserKey`) returns only an opaque `#[wasm_bindgen]` struct handle, never `Vec<u8>`/`&[u8]` of the key bytes; enforced by Task 1's acceptance-criteria grep and by design (only `randomSalt`, non-secret, returns raw bytes) |
| T-01-02 | Tampering | `scripts/build-wasm.sh` / `wasm-bindgen` crate↔CLI schema | medium | mitigate | Exact version pin (`=0.2.126`) single-sourced from `crates/pv-wasm/Cargo.toml`; build script parses it rather than hardcoding a second literal, so a version bump can only happen in one place and a mismatch fails loudly at build time rather than producing a corrupted artifact |
| T-01-SC | Tampering | `cargo install wasm-bindgen-cli` (supply chain) | low | accept | `wasm-bindgen`/`wasm-bindgen-cli` verified `OK` in RESEARCH.md's Package Legitimacy Audit (crates.io, 8.3M downloads/week, canonical `wasm-bindgen/wasm-bindgen` GitHub org); exact-version pinning prevents silent drift to a future compromised release |

</threat_model>
