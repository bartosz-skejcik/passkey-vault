<objective>
Implement the client-side half of AUTH-03: a new WASM export that mirrors the existing password
wrapping-key derivation but for PRF output, and the two-ceremony enrollment orchestration + dialog UI
that drives it. Per 03-RESEARCH.md's Architectural Responsibility Map, PRF extension evaluation and
UK wrapping are hard zero-knowledge constraints of the Browser/Client tier — this plan is where that
boundary is actually implemented, not just documented.

This plan has no analog in the existing codebase (03-PATTERNS.md flags both `enroll.ts` and
`EnrollPasskeyDialog.tsx` as "No Analog Found") — it is genuinely new WebAuthn+PRF+WASM orchestration,
not a refactor of an existing pattern.

Purpose: give a logged-in, unlocked user a working "+ Dodaj passkey" flow that produces a real,
server-persisted, passkey-wrapped copy of their User Key.
Output: `WasmWrappingKey.fromPrf`, `lib/passkeys/{api,enroll}.ts`, `EnrollPasskeyDialog.tsx` — testable

<interfaces>
Backend contract this plan calls against (implemented by Plan 03-01, already on disk):
```
POST /api/passkeys/register/start   { display_name: string }
                                     -> { state_id: string, challenge: CreationChallengeResponse, prf_salt: string /* base64 STANDARD */ }
POST /api/passkeys/register/finish  { state_id: string, credential: <credential.toJSON() shape> }
                                     -> { passkey_id: string, name: string, prf_challenge: RequestChallengeResponse, prf_state_id: string, prf_salt: string }
POST /api/passkeys/{id}/prf-wrap    { state_id: string, credential: <assertion.toJSON() shape>, prf_wrapped_uk: string }
                                     -> { prf_capable: true }
```
`CreationChallengeResponse`/`RequestChallengeResponse` are `{ public_key: {...} }` (snake_case key —
webauthn-rs's own `#[serde(rename_all = "camelCase")]` renders the OUTER struct's field as
`publicKey`, verify the exact casing against Plan 03-01's actual response once it's on disk before
assuming; do not guess). Every field INSIDE those objects (`challenge`, credential `id`/`rawId`,
`attestationObject`, `clientDataJSON`, `signature`) is base64url-no-padding per the WebAuthn wire
format — use the browser's native JSON parsing methods below, never this app's existing
`base64Encode`/`base64Decode` helpers (those are standard-base64 and will corrupt base64url data).
`prf_salt` is the ONE field in these responses that IS standard base64 (app-invented value, not part
of the WebAuthn wire format) — decode it with the existing `base64Decode` from `@/lib/auth/api`.

Native WebAuthn JSON serialization methods (Baseline 2025 — broadly supported by all major browsers
well before this project's 2026-07-14 planning date; verified via MDN during planning, not assumed
from training data):
```ts
PublicKeyCredential.parseCreationOptionsFromJSON(json): PublicKeyCredentialCreationOptions
PublicKeyCredential.parseRequestOptionsFromJSON(json): PublicKeyCredentialRequestOptions
credential.toJSON(): RegistrationResponseJSON | AuthenticationResponseJSON  // instance method
```
These exist specifically to eliminate hand-rolled base64url<->ArrayBuffer conversion code — use them
instead of writing a `decodeChallenge`/manual-ArrayBuffer-conversion helper. This SUPERSEDES
03-RESEARCH.md's own Code Examples section, which sketched a hand-rolled `base64Decode(challenge)`
approach reusing this app's STANDARD-base64 helpers — that sketch predates re-verifying the wire
format is base64url, not standard base64, and would corrupt the challenge/credential fields it
touches. The native methods are strictly simpler and correct; use them.

Existing `lib/crypto/index.ts` exports you will use: `getUnlockedUserKey(): WasmUserKey | null`,
`wrapUserKey(wrappingKey, userKey): string`, and (added by Task 1 of this plan) `WasmWrappingKey.fromPrf`.

`lib/vault/api.ts`'s `apiJson<T>` wrapper pattern (copy verbatim into `lib/passkeys/api.ts`, do not
duplicate `apiFetch`/error-handling logic — reuse `apiFetch`/`ApiClientError` from `@/lib/auth/api`).

    ```ts
    export type EnrollStep = "step1" | "step2" | "doneWithPrf" | "doneNoPrf" | "cancelled" | "failed";

    export async function enrollPasskey(name: string, onStep: (step: EnrollStep) => void): Promise<void> {
      const uk = getUnlockedUserKey();
      if (uk === null) throw new Error("vault must be unlocked to enroll a passkey");

      onStep("step1");
      let passkeyId: string, prfChallenge: unknown, prfStateId: string, prfSaltB64: string;
      try {
        const start = await registerStart({ display_name: name });
        const creationOptions = PublicKeyCredential.parseCreationOptionsFromJSON(
          (start.challenge as { publicKey: unknown }).publicKey,
        );
        const credential = (await navigator.credentials.create({
          publicKey: { ...creationOptions, extensions: { prf: {} } },
        })) as PublicKeyCredential;
        const finish = await registerFinish({ state_id: start.state_id, credential: credential.toJSON() });
        passkeyId = finish.passkey_id;
        prfChallenge = finish.prf_challenge;
        prfStateId = finish.prf_state_id;
        prfSaltB64 = finish.prf_salt;
      } catch (e) {
        onStep(isNotAllowedError(e) ? "cancelled" : "failed");
        return;
      }

      onStep("step2");
      try {
        const requestOptions = PublicKeyCredential.parseRequestOptionsFromJSON(
          (prfChallenge as { publicKey: unknown }).publicKey,
        );
        const assertion = (await navigator.credentials.get({
          publicKey: { ...requestOptions, extensions: { prf: { eval: { first: base64Decode(prfSaltB64) } } } },
        })) as PublicKeyCredential;

        const results = assertion.getClientExtensionResults() as { prf?: { results?: { first?: ArrayBuffer } } };
        const prfBytes = results.prf?.results?.first;
        if (prfBytes === undefined) {
          onStep("doneNoPrf");
          return;
        }
        const prfArray = new Uint8Array(prfBytes);
        const wrappingKey = WasmWrappingKey.fromPrf(prfArray); // zeroizes prfArray as a side effect
        const wrappedJson = wrapUserKey(wrappingKey, uk);
        await prfWrap(passkeyId, { state_id: prfStateId, credential: assertion.toJSON(), prf_wrapped_uk: wrappedJson });
        onStep("doneWithPrf");
      } catch {
        // Any step-2 cancel/failure is STILL a successful enrollment: the
        // credential from step 1 already exists server-side. Routing this to
        // "cancelled"/"failed" (as if nothing happened) would let a naive
        // "retry" restart from Name entry and create a second, orphaned
        // credential while the first silently remains enrolled as a
        // legitimate no-PRF passkey (03-RESEARCH.md Pitfall 3).
        onStep("doneNoPrf");
      }
    }
    ```
