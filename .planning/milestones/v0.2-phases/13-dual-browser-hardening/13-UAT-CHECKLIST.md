### Correction, dated 2026-07-19 (debug session `.planning/debug/resolved/firefox-injection-csp-blocked.md`)

**Row 23's claim was INCOMPLETE, not honest as originally worded.** The row states Firefox's `injectScript()`-based mechanism "produces the IDENTICAL outcome to Chrome's declarative `world:'MAIN'`" — this was verified ONLY against this walk's local third-party RP fixture page, which serves NO `Content-Security-Policy` header at all. On any REAL site with a non-permissive CSP (confirmed live by Bartek on `github.com/sessions/two-factor/webauthn`, and reproduced in the debug session via a throwaway extension against a real CSP-strict fixture), WXT's `injectScript()` helper picks an INLINE `script.text = <fetched source>` strategy for this project's MV2 Firefox build — an inline script element is blocked by the page's own `script-src-elem` CSP directive, so `page-bridge-firefox.js` never installed there and every real-world strict-CSP site silently fell through to native WebAuthn instead of the provider. The outcome therefore did NOT match Chrome's on any strict-CSP site, only on CSP-free fixtures — row 23's local-fixture-only test scope, not a fabrication, is what let this ship undetected through 13-04's own walk.

**Fixed** by replacing the injection mechanism's DOM-construction strategy: `injectPageBridgeFirefoxScript()` (a small local function in `content-relay.content.ts`, no longer WXT's own `injectScript()` helper) always sets `script.src = browser.runtime.getURL(...)` — a `moz-extension://` `web_accessible_resources` load, confirmed empirically (real Firefox + a CSP-strict fixture) to be exempt from the page's CSP even though inline script content is not. Row 17's "(via Firefox's `injectScript()`-based `page-bridge-firefox.js`, per D-08/12-03)" phrasing is similarly superseded by this mechanism change — the injection call name changed, the outcome (a working provider shim on the RP fixture used in that row) did not. No `strict_min_version` change was needed; the CSP-exemption property used by the fix is not version-gated (unlike the declarative `world:'MAIN'` alternative this debug session considered and rejected — see that session's own Eliminated section). New CSP-STRICT fixture coverage closing this exact blind spot was added to `extension/e2e-firefox/run-core.cjs` per that debug session's own TESTS mandate.
