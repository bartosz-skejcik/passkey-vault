<ui_contract>
Lifted from 10-UI-SPEC.md — the binding visual/interaction decisions (each is a `must_have` above too):

- **Design system:** Tailwind v4 + DaisyUI 5 (`btn`, `badge`, `alert`, `radial-progress`, `skeleton`), `lucide-react` icons. NOT shadcn — do not init it. The extension popup's `package.json` (Phase 9) should already carry `daisyui@5.6.18` / `lucide-react@1.24.0` / `tailwindcss@4.3.2`; confirm at exec, flag if divergent (UI-SPEC Registry Safety).
- **Width:** fixed 360px. Truncate origins/labels; never design wider. Icon-only buttons are `h-8 w-8` (32px), not the 44px touch minimum — this is a mouse/trackpad popup.
- **Type→icon map:** reuse TypePicker's exact mapping — `Vault` (login), `CreditCard` (card), `IdCard` (identity), `Timer` (totp).
- **Color:** coral primary (`#E16540`) only on the Wypełnij button + TOTP fill-icon active state + the countdown ring. NO teal (reserved for passkeys, Phase 12). Card/identity confirm is NEUTRAL base-content, NOT warning-yellow — an extra consent step is not an alarm.
- **Copy:** bilingual PL/EN via the `{pl,en}` dictionary convention; PL primary. Fuzzy Bubbles font permitted ONLY in the empty-state copy, never in fill/confirm/error copy ("security UI zawsze czytelne").
- **States:** loading (single skeleton row, <200ms expected), populated-single, populated-multiple (the list IS the picker), empty (`AutofillEmptyState`, Fuzzy Bubbles `🤷`), error/restricted (`alert alert-error`, plain, no emoji), fill-in-progress (`loading loading-spinner loading-xs` in the button, disabled to prevent double-fill), fill-failed (reuse Phase 9's toast).
- **Silent iframe refusal:** a cross-origin subframe with no match looks identical to any innocuous no-match — no "blocked for security" copy. Deliberate (UI-SPEC Copywriting Contract).
</ui_contract>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| popup ↔ background | Extension-privileged both sides; the popup issues the user's gesture-backed autofill requests. |
| popup ↔ clipboard | The TOTP copy writes a derived code to the system clipboard with an auto-clear timer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-22 | Information Disclosure | Popup holding decrypted password/card values | high | mitigate | The popup never receives them — `autofill.fill`'s response is value-free; only the TOTP code transits the popup, and only to the auto-clearing clipboard (reused v0.1 behavior). |
| T-10-23 | Information Disclosure | TOTP code left on the clipboard indefinitely | low | mitigate | `copyWithAutoClear` clears after the configured 30–60s, identical to the web app. |
| T-10-24 | UI-redress / accidental fill | A single click filling sensitive card/identity data | medium | mitigate | D-12's mandatory second inline confirm for card/identity (Task 2 + Task 3 test); login keeps the single-click bar (D-03) which is already gesture-gated by popup-open + Wypełnij. |
</threat_model>
