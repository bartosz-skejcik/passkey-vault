<architecture_note>
- The overlay is plain TS + DOM (NO React — the content script is not a React entrypoint; adding
  React to an all_urls content script bloats every page and risks host-page conflicts). Build it as
  a small imperative controller that owns one closed shadow root attached to a single host element
  the content-relay appends to document.documentElement.
- `attachShadow({ mode: "closed" })` — closed so the host page's JS cannot reach in via
  element.shadowRoot. (Defense in depth; the real isolation is the ISOLATED world + that we render
  only metadata.)
- The overlay NEVER receives or stores a plaintext value. onPick(itemId, kind) → content-relay
  sends autofill.fillFrame → background pushes content.fill → fill-dom writes it. The overlay is
  told nothing about what was written.
- Dismissal state (close / block-this-site) is per-page-session, held in the content script's
  module scope (a Set of "dismissed"/"blocked" flags). Do not persist to storage this phase.
- Focus handling: a single `focusin` listener on document, debounced/guarded, that checks whether
  the focused element is one of the detected fields (reuse detect-login/detect-totp/detect-scored
  results) and, if so and this frame has matches, anchors Surface A to it. Do NOT add a
  whole-document MutationObserver (10-RESEARCH Pitfall 4). Re-detect lazily on focusin.
- Cross-origin subframe: the overlay only ever calls autofill.fillFrame for its OWN frame; 10-09's
  handleFillFrame re-verifies origin. A subframe with no matching items simply renders nothing.
</architecture_note>
