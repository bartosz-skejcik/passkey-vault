<objective>
Build the ISOLATED-world `content-relay` content script — the phase's only page-touching code — and the shared `fill-dom.ts` writer that makes fills survive React/Vue controlled inputs. The content-relay senses (which field families are present) and writes (values handed to it by the background); it renders nothing and decrypts nothing.

Purpose: 10-CONTEXT.md D-01/D-02 and 10-UI-SPEC.md's Scope Note require exactly this: a pure DOM sensor/writer with no in-page UI and no key material. 10-RESEARCH.md Pitfall 5 is the load-bearing detail — a naive `input.value = x` leaves a framework's state stale, so the form submits empty despite showing the value; the native-setter workaround is the difference between "looks filled" and "actually filled".
Output: `fill-dom.ts` + tests, and `content-relay.content.ts` + tests.
</objective>

    - Test 1: `setNativeValue(input, "x")` sets the value AND dispatches a bubbling `input` event and a `change` event (assert both fire and bubble; assert `input.value === "x"`).
    - Test 2: `setNativeValue` uses the prototype's value setter — simulate a React-style instance-level setter override on the element and assert the native prototype setter still writes through it (spy on the prototype descriptor's `set`).
    - Test 3: `fillValues({type:"login", username, password}, targets)` writes username into the username element and password into the password element; a login with `username: null`/no username target fills only the password.
    - Test 4: `fillValues` for a card writes cardholderName/number/expiry/cvv into the resolved slot elements; a split-expiry target (month+year elements) receives the parsed month and year rather than the raw `expiry` string.
    - Test 5 (vanished field): `fillValues` where a target element is detached from the document (SPA removed it) returns `{ ok: false, filledCount }` WITHOUT throwing, so the caller can report a fill failure.
    - Test 6 (identity): `fillValues` for an identity writes firstName/lastName/email/phone/address into their slots; missing slots are skipped silently.
  </behavior>
  <action>
  Create `extension/lib/autofill/fill-dom.ts`.

  `setNativeValue(input: HTMLInputElement | HTMLTextAreaElement, value: string): void` — resolve the value setter from the correct prototype (`HTMLInputElement.prototype` / `HTMLTextAreaElement.prototype`, chosen by tag) via `Object.getOwnPropertyDescriptor(proto, "value")`, call `descriptor.set.call(input, value)` to bypass any framework-patched instance setter, then dispatch `new Event("input", {bubbles:true})` and `new Event("change", {bubbles:true})`. This is 10-RESEARCH.md's "Native-setter DOM fill" example; follow it exactly — the prototype-setter detail is the whole point (Pitfall 5).

  `fillValues(values: FillValues, targets: FillTargets): { ok: boolean; filledCount: number }` — where `targets` is the per-kind element map the content-relay resolved via the detectors. Switch on `values.type`. For each slot with both a value and a live target element (`document.contains(el)` true), `setNativeValue`. For card `expiry` when the target is a split month/year pair, parse the stored `expiry` (accept `MM/YY`, `MM/YYYY`, `MM / YY`) into month + 2-or-4-digit year to match each sub-field's expected width; if parsing fails, fall back to writing the raw string into a single expiry field if one exists, else skip that slot. Count successful writes; return `ok: filledCount > 0` (a fill that lands nothing is a failure the popup should surface). Never throw on a missing/detached target — skip and keep going.

  Do NOT import any crypto module. Do NOT read any input's existing value and return it (the flagged prohibition). This module only writes.

  Write `fill-dom.test.ts` under jsdom with the 6 behaviors. jsdom DOES honour prototype value-setter descriptors and dispatches events, so Tests 1/2 are genuinely exercised (the one thing jsdom cannot reproduce is a real React reconciler — that's the plan 10-07 UAT's job, noted in 10-VALIDATION.md Manual-Only).

  In `main(ctx)`, register a single `browser.runtime.onMessage` listener that dispatches the background→content payloads (`ContentDetectRequest`/`ContentFillRequest` from 10-01):
  - `content.detect`: run `detectLogin(document)`, `detectTotp(document)`, `detectCard(document)`, `detectIdentity(document)`; build `DetectedFields` booleans (`login` true when a password field was found, etc.) and `hasOtpField`. A page-load or observer-driven scan that pushes to the background would (a) violate the gesture gate spirit and (b) reintroduce the naive-whole-document-observer performance trap (10-RESEARCH.md Pitfall 4). If a later phase needs live re-detection, it adds a scoped, debounced observer then — record this as a deliberate omission, not a gap.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| content-relay (ISOLATED) ↔ page DOM | Runs adjacent to a potentially hostile page. ISOLATED world isolates its CODE from the page, but any value it WRITES is page-visible (unavoidable — that is what autofill is). |
| content-relay ↔ background (`runtime.onMessage`) | Receives plaintext fill values for one write; must not persist or re-read them. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-18 | Information Disclosure | Content-relay reading page values and exfiltrating them | medium | mitigate | `content.detect` returns booleans only (Test 1); the module never reads a field value back (flagged prohibition). Capture (reading values with consent) is Phase 11's separate concern. |
| T-10-19 | Information Disclosure | Fill values persisted in a module-level variable or storage beyond the single write | high | mitigate | `fillValues` is a pure write; no module-level cache of values, no storage write (10-RESEARCH.md V8: plaintext is transient). Grep confirms no `storage`/`localStorage` in the file. |
| T-10-20 | Malicious/Untrusted Code | Constructing code from DOM-read strings | high | mitigate | Detectors and fill-dom never `eval`/`new Function` on DOM strings (10-RESEARCH.md V10); grep-auditable. |
| T-10-21 | Denial of Service | Unscoped MutationObserver on a heavy SPA | low | avoid | No observer added this phase — detection is on-demand only (Pitfall 4). |
