<objective>
Build the one genuinely new crypto primitive Phase 25 needs: a rewrap-only operation that moves an
item's Cipher Key from an old CollectionKey's wrap to a new one without ever touching the item's
payload ciphertext. This is the primitive both the server-side re-key transaction (Plan 25-03) and the
client-side batch orchestration (Plan 25-07) build on — get its correctness proven here, once, rather
than trusted implicitly at every call site.

Purpose: KEY-02's rewrap-only guarantee ("removing a member rewraps keys only") is only real if this
function's own type signature makes touching `enc_data` a compile-time impossibility, and its crypto
correctness (round trip, wrong-key rejection, AAD separation) is proven independently of any server or
client code that will call it.
Output: `rewrap_item_key_for_collection` in `pv-core`, `rewrapItemKeyForCollection` in `pv-wasm`, both
with real-crypto regression tests.
</objective>
