<objective>
Build the account-deletion endpoint this codebase has never had, closing the gap ARCHITECTURE.md §4.3
flagged: today's `ON DELETE CASCADE` on `users` drops `family_members` rows via FK but never triggers a
collection re-key, and no code path in this repository has ever deleted a `families` or `collections`
row — so the FK-ordering hazard (`families.owner_user_id`/`vault_items.collection_id` both lack `ON
DELETE` actions) is worked out here from the schema directly, with no prior precedent to copy.

Purpose: FAM-10 requires account deletion to run the SAME re-key path as explicit removal before
dropping the user row — for a plain member. For an owner, CONTEXT.md's locked decision is dissolution,
not re-key: the whole family ends, in a provably FK-safe order. This is the phase's one place with
literally no code analog anywhere in the repository (per 25-PATTERNS.md's "No Analog Found" section).
Output: `DELETE /api/auth/account`, wired into `mod.rs`, and `tests/account_deletion.rs` proving all
three branches plus the FK-enforcement-is-real proof.
</objective>
