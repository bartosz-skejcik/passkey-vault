<objective>
Wire KEY-01's last unowned clause (per A-2/A-3, ROADMAP Phase 26 SC 5): the web app must actually
CALL `ensureOwnIdentityKeypair` on every unlock. Phase 21 built the crypto, Phase 22 built and
proved the idempotent server-side upsert, but nothing has ever invoked it — "every account has a
keypair" is possible today, not true. This plan makes it true, fire-and-forget, at all 4 places
`setUnlockedUserKey` is called.

Purpose: Every other surface in this phase (fingerprint display, sharing, avatar stacks) depends
on the caller having a published public key. Without this trigger, none of it has real data to
show for an upgraded pre-v0.4 account or a brand-new one until some OTHER code path happens to
call `ensureOwnIdentityKeypair` (today only invite-generation/removal-flow does).
Output: A shared `publishOnUnlock` wrapper, wired at all 4 existing `setUnlockedUserKey` call sites.
</objective>
